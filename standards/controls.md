# 控件

- 状态：draft
- 来源：从「现在」页的试做原型沉淀来（本机的 katachi-trial-now 仓库，now-prototype 分支，提交 12d4c66）。用户定的有三点（2026-11-08 看过原型后确认）：框只给要打字的地方，能点的靠底色，下划线只给链接；空着的提交按钮，只有一个输入框时禁用，要填好几项时一直能点；分段选择里选中的一段用实心。写明 WCAG 的有出处，其余都是提案，用户还没确认

「交互」这一层的第一页：按钮、输入框、下拉、分段选择、勾选框和链接，什么时候用哪种，长什么样，七种状态各是什么样子。这一页只用前三页的角色：字见[排版](typography.md)，颜色见[颜色](color.md)，尺寸、圆角和描边见[间距和形状](space.md)。提示放在哪、留多久，撤销和保存这些反馈还没有写。

## 三条规则

用户定的。样子跟着「它是什么」走，看一眼就知道哪里能打字、哪里能点、哪里会跳走。

**1. 框给要打字的地方。** 输入框和多行输入画框，用 `color.control`。勾选框本身就是一个框。别的东西不画框：按钮、下拉、分段选择和内容都不画。

**2. 底色给能点的东西。** 按钮、下拉、分段选择靠底色认出来。主按钮实心，其余用 `color.fill`。有文字的按钮不画边框也认得出，WCAG 1.4.11 不要求它有边框。

**3. 下划线只给链接。** 点了会跳到别处的文字才有下划线，写在 [color.css](color/color.css) 里。按钮和下拉都不加；在原地做一件事的，用按钮，不用链接。

这三条的代价：每个操作都要占一块底色，没有只是一行字的按钮；底色很淡，控件放在和它同色的底上会看不见，要按下面「尺寸和形状」换一级。

## 用哪种

| 控件 | 什么时候用 | 什么时候不用 | 样子 |
|---|---|---|---|
| 主按钮 | 一组操作里最常做的那一个：保存、提交、记下 | 这一组已经有一个主按钮了 | 实心，`color.accent-solid`，字加粗 |
| 次按钮 | 同一组里的其他操作 | 点了跳到别的页面，用链接 | `color.fill` 的底 |
| 小按钮 | 跟着某一条的操作，放在说明那一行：撤销、展开、再试一次 | 一组的主要操作 | 底色，字用 `type.size.caption`，高 `constraint.target.web-min` |
| 危险按钮 | 不能撤销的操作，比如删除 | 能撤销的，用次按钮，做完给「撤销」 | 实心，`color.error-solid` |
| 输入框 | 打一行字 | 选项是固定的几个 | 框 |
| 多行输入 | 打一段字 | 只有一行的内容 | 框，跟着内容长高，不露拖拽角 |
| 分段选择 | 2–4 个短选项选一个，选了马上生效 | 选项多、名字长，或者地方不够 | 底色，选中的一段实心 |
| 下拉 | 选项多、名字长，或者地方不够 | 2–4 个短选项，用分段选择 | 底色，名字写在里面，宽度跟着选中的那一项 |
| 勾选框 | 开或关一件事；在清单里勾掉一项 | 几个选项只能选一个，用分段选择或下拉 | 框，勾上后实心加勾 |
| 链接 | 跳到别处 | 在原地做一件事，用按钮 | 下划线 |

一组操作里只放一个主按钮。只有一个操作时，也可以不用主按钮。

## 状态

| 状态 | 怎么表示 | 要注意 |
|---|---|---|
| 焦点 | `color.focus` 的环，粗 `stroke.thick`，往外隔 `stroke.thick`。带按钮的输入框、下拉和分段选择把环画在外面那一层 | 用键盘走到哪都看得见。用 `:focus-visible`，鼠标点按钮时不画 |
| 选中 | 分段选择：选中的一段实心，`color.accent-solid` 配 `color.on-solid`，字加粗。勾选框：实心加勾。列表的当前项：`color.selected` 的底加竖线 | 不只靠底色。`color.selected` 和悬停是同一级，灰阶里也分不开 |
| 禁用 | 字用 `color.ink-disabled`，底色和形状不变，主次按钮禁用后一个样。输入框的框换成 `color.line` | 能不禁用就不禁用，见下面「空着的提交按钮」 |
| 加载 | 样子不变，前面加转圈，字换成「保存中」这样的「……中」。写 `aria-disabled="true"`，不写 `disabled` | `disabled` 会让正在按的按钮丢掉焦点。重复点击由脚本拦住。减少动态时不转 |
| 空状态 | 输入框空着时显示提示文字，用 `color.ink-muted`。列表空了时，先说现在是空的，再说接下来能做什么，给一个能直接做的操作 | 提示文字不代替标签：打了字它就看不到了 |
| 错误 | 输入框的框换成 `color.error-line`，写 `aria-invalid="true"`；说明写在下面，用 `color.error`，用 `aria-describedby` 连到输入框。操作失败时，在出事的地方旁边放提示：图标、出了什么事、怎么办，能重试的给「再试一次」 | 打的字不能丢 |
| 成功 | 在出事的地方旁边放提示：图标加一句话，`color.success`；能撤销的给「撤销」 | 提示放在哪、留多久还没定，见最后 |

## 空着的提交按钮

用户定的。

- **只有一个输入框**（记一条、搜索、发消息）：空着时提交按钮禁用，打了字才能点。一看就知道差什么。
- **要填好几项的表单**：提交按钮一直能点。点了以后，没填的每一项下面写清缺什么，焦点移到第一个没填的地方。按钮一禁用，人不知道还差哪一项。

提交之后清空输入框时，先把焦点放回输入框，再禁用按钮，不然焦点会丢。

## 尺寸和形状

- **高度**：写 `min-block-size: var(--size-control)`，跟着疏密变；触屏上是 `size.control-touch`，[space.css](space/space.css) 已经写好。小按钮、小下拉和小分段高 `constraint.target.web-min`，触屏上能点的范围往外扩到 `size.control-touch`，看起来不变。
- **左右留白**：`space.inset`，小的用 `space.near`。
- **圆角**：`radius.control`，跟着 `data-radius` 整体换。分段选择里选中的一段和外圈隔一条 `stroke.thick`，圆角也小这么多（见[间距和形状](space.md)的嵌套圆角）。勾选框的圆角最多是方框的四分之一：默认的 8px 圆角配 18px 的方框几乎是圆的，看起来像单选。
- **底色和下面那一层分得开**：控件放在灰 1 上（页面、浅色的面、深色下面后面的底），底色、悬停、按下是灰 3、4、5。放在灰 3 上时要换：浅色下面后面的底 `color.backdrop` 是灰 3，那里的控件用灰 1、2、4，像面一样亮出来；深色下的面 `color.panel` 是灰 3，面上的控件用灰 5、6、7。浅色不用灰 5，是因为次要文字（灰 11）在灰 5 上只有 4.48。写法见[面](space/panel.html)。
- **勾选框**：方框 `size.check`。带文字时整个标签都能点，至少 `size.control` 高，文字换行时方框对着第一行；清单里不带文字的，能点的范围是 `size.control` 见方，名字写在 `aria-label`。
- **多行输入**：跟着内容长高，最高 `size.input-max`，再长在框里滚动，第一行的位置和单行的输入框一样。不支持 `field-sizing` 的浏览器停在两行高，在框里滚动。
- **下拉**：自己画底色和箭头，弹出来的选项列表用系统的。
- **图标**：跟着字号和字的颜色，和文字的中线对齐。图标只补充文字，不单独说事；只有图标的按钮，要用 `aria-label` 写名字。

## 内容

- 按钮里的字太长时换行，不截断。放的是用户的内容（文件名、任务名）时，单行省略，全名在别处看得到。
- 下拉跟着选中的那一项变宽，最宽到放它的地方那么宽，不撑破版面。
- 中英文混排、长文字、窗口宽度为 `constraint.reflow.width` 时，控件不溢出，主要操作不被挤掉。

## 平台

原生平台用系统控件，不按这一页重画：系统控件自带尺寸、形状和七种状态，用的人认得的是系统的样子。三条规则在系统控件里不一定成立，比如 iOS 的按钮常常只有彩色的字，没有底色，这时跟着系统。

| 平台 | 用什么 |
|---|---|
| Web | 这一页的 [controls.css](controls/controls.css) |
| macOS、iOS | SwiftUI，或者 AppKit、UIKit 的系统控件 |
| Windows | WinUI 的系统控件 |
| Android | Material 的组件 |
| 终端 | 没有控件的样子：要输入时给提示符，选项用数字或方向键，当前项用 `>` 标出 |

只在 macOS 的 Chromium 上渲染过。Safari、Firefox、Windows 和安卓都没有看过，要在目标环境再查一遍；Safari 和 Firefox 对 `field-sizing` 的支持尤其要看。原生平台的控件没有在原生环境运行过。

## 怎么实现

[controls.css](controls/controls.css) 是 Web 的参考实现，只写角色，可以整个复制进产品。先引入 tokens.css、type.css、color.css 和 space.css。

| 控件 | 写法 |
|---|---|
| 按钮 | `<button class="btn">`；主按钮加 `primary`，危险加 `danger`，小按钮加 `small` |
| 输入框 | `<input class="input">`，多行用 `<textarea class="input">` |
| 带按钮的输入框 | `<div class="input-box">` 画框，里面放 `.input` 和 `<div class="input-foot">` |
| 说明 | 输入框下面的 `<p class="hint">`，出错时加 `is-error` |
| 下拉 | `<label class="select"><span class="select-label">名字</span><select>…</select>箭头图标</label>` |
| 分段选择 | `<div class="segmented" role="radiogroup">`，每段是 `<label><input type="radio">名字</label>` |
| 勾选框 | `<label class="check"><input type="checkbox"><span>文字</span></label>`；不带文字的加 `alone` |
| 提示 | `<p class="note is-error">` 里放图标、一句话和小按钮；成功是 `is-success`，警告是 `is-warning`，保存中是 `is-pending` |

- 焦点环来自 color.css 的 `:focus-visible`，包了一层的控件把环画在外层。
- 强制颜色模式下底色会被去掉：controls.css 给按钮、下拉和分段选择补上边框，选中的一段用系统的高亮色，勾选框交给系统画。
- 转圈多快是临时的值，写在 controls.css 开头，等动效那一轮再定。

下面的一览把每种控件的状态放在一起。悬停、按下和焦点那几格是画出来的静态样子；「空着的提交按钮」那一节可以操作。可以切换明暗、强调色、疏密和圆角。

## 做完检查

- 看样子分得出能做什么：要打字的有框，能点的有底色，会跳走的有下划线；别的东西没有框，也没有下划线。
- 一组操作里最多一个主按钮。
- 七种状态都有样子，用的是上面的角色；加载时焦点还在按钮上。
- 用 Tab 走一遍，每个控件的焦点环都看得见；分段选择用方向键换。
- 看灰阶截图，选中的一段、勾上的框都分得出来。
- 控件放在灰 3 的底上时换了底色，看得见，里面的次要文字不低于 `constraint.contrast.text`。
- 输入框和勾选框的框、选中的一段，和旁边颜色的对比度不低于 `constraint.contrast.non-text`。tokens 里的配对由 `node tools/check.mjs` 算。
- 强制颜色模式下，按钮还有边框，选中和焦点还看得出。
- 触屏上能点的范围不低于 `size.control-touch`。
- 长文字、中英混排、窗口宽度为 `constraint.reflow.width` 时不溢出，主要操作没被挤掉。
- 空着的提交按钮照上面分开做。

## 还没定，问用户

1. 提示放在哪、留多久，撤销怎么做？原型里放在出事的地方旁边，不浮起来；成功的留到下一次操作，出错的留到解决。建议下一页「反馈」用原型当证据来定。
2. 图标用哪一套？现在样例里是 agent 画的几个线条图标，没有授权问题。建议先这样，用到十几个以上再挑一套开源的。
