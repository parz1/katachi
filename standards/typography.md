# 排版

- 状态：draft
- 来源：agent 起草的提案。用户定的有四点：字体属于排版，字体用什么背后有哲学，不定死成一种，字默认不出声（2026-11-07 看过草稿后确认）。写明 W3C 或 WCAG 的有出处，写明实测的是这里量出来的，其余都是提案，用户还没确认

字体是排版的一部分，这一页一起写。先说为什么这样用字，再说默认怎么做、什么时候换。颜色见[颜色](color.md)，间距见[间距和形状](space.md)。

## 四个主张

**1. 先看人怎么读。** 扫一眼、照着操作、坐下来读、上下对数字，要的东西不一样，所以样式按读法分，不是全站一种字号、一种行高。读的人调过字号或系统设置，听他们的。

**2. 先把版排好，字体才有意义。** 版决定好不好读，字体决定用什么语气说话。层次靠字号、留白和位置建立，不靠某一款字体撑着。换一款字体，层次要还在；终端选不了字体，层次也要还在。

**3. 字默认不出声，要出声得有理由。** 大多数界面是工具，字不该被注意到，所以默认用系统字体：不用下载，跟着系统走，读的人也熟悉。文字本身就是产品，或者有人在说话时，才换字体。用户已确认这一条。

**4. 中文先对。** 先把中文排对，英文和数字跟着中文走。从英文出发的字体设置，到中文就出问题，下面「中文的规矩」有实测。

这四条的代价：默认没有字体上的面貌，各系统看起来也不一样，面貌要靠排版和颜色。中文段落里的英文用中文字体自带的字形，不如专门的英文字体精致。只做英文的产品，第 4 条要反过来。

## 四种读法

每段字先问：读的人这一眼要干什么。

| 读法 | 例子 | 最在乎 | 用什么样式 |
|---|---|---|---|
| 操作 | 按钮、标签、输入框、菜单 | 一眼认出，放得下 | `ui` |
| 扫读 | 标题、导航、列表、卡片 | 层次和位置，长短不一也整齐 | `title-*`、`ui`、`caption` |
| 阅读 | 正文、文档、说明、长回复 | 读久了不累，靠行长和行高 | `read`、`read-large` |
| 比对 | 表格、金额、时间、代码 | 上下对得齐 | `ui` 加等宽数字，代码用等宽字体 |

## 字体：默认和什么时候换

| 这段字要做什么 | 用什么 | 什么时候用 | 什么时候不用 | 代价 |
|---|---|---|---|---|
| 退到后面（默认） | 系统字体，`type.family.sans` | 工具、后台、设置，以及没有理由换的地方 | 想让文字本身被记住时 | 没有面貌，各系统不一样 |
| 像书一样 | 思源宋体，回退到系统宋体，`type.family.serif` | 文字本身就是产品：文档、长文、读书 | 操作和比对；比 `type.size.read` 小的字，宋体的横笔太细 | 网页要下载（这个样例 0.8 MB），原生应用要打包；网页版的破折号偏短 |
| 带着语气 | 霞鹜文楷，回退到系统楷体，`type.family.kai` | 有人在说话：写给读者的信、笔记、欢迎语 | 操作和比对；错误提示和正式通知 | 同上（这个样例 0.6 MB）；不够正式；英文和数字也是手写感 |
| 对得齐 | 西文字体在前，`type.family.latin` | 表格、金额、时间；标了 `lang="en"` 的纯英文 | 中文段落 | 中文段落里用它，破折号和省略号会变短 |
| 写代码 | 等宽字体，`type.family.mono` | 代码、校验值 | 其他地方 | 中文和英文的宽度不成整数倍，对不齐 |

- 一个界面只让一款字体出声。操作和比对的字不换，下面 3 个样例的表单、列表和表格完全一样。
- 产品有自己的字体时用产品的，但要过一遍「做完检查」。
- 中文字体一个字重的全部切片约 3–5 MB（实测 Noto Sans SC 3.4 MB，文楷 4.4 MB）。网页按需下载，原生应用要打包完整字体，安装包至少大这么多。思源字体和文楷都是 SIL OFL 1.1，可以打包；苹方和 SF 不能分发。
- 这样分工有传统依据：W3C 的[中文排版需求](https://www.w3.org/TR/clreq/)说宋体是中文排版最常用的字体，楷体常用于引言、摘句、对话，黑体多用于标题和强调，受网页和数字出版影响才开始排内文。

下面 3 种排法用同一份内容，字体、字号、行距、段落和标题的摆法一起变。默认这一版可以直接换字体，版式不动，用来看层次是不是真的还在。

## 样式

Web 用下面的 token，[type.css](typography/type.css) 是现成的实现，可以整个复制进产品。

| 样式 | 用在 | 字号 | 行高 |
|---|---|---|---|
| `title-l` | 页面主标题，一页一个 | `type.size.title-l` | `type.line.title-l` |
| `title-m` | 区块标题 | `type.size.title-m` | `type.line.title-m` |
| `title-s` | 小节标题、弹层标题 | `type.size.title-s` | `type.line.title-s` |
| `read` | 连续阅读的正文 | `type.size.read` | `type.line.read` |
| `read-large` | 宋体或楷体的正文 | `type.size.read-large` | `type.line.read-large` |
| `ui` | 按钮、标签、输入框、菜单、列表、表格 | `type.size.ui` | `type.line.ui` |
| `caption` | 时间、来源这类次要说明 | `type.size.caption` | `type.line.caption` |

- 层次先用字号和留白，再用字重，最后才用颜色，而且不能只靠颜色。一屏里超过 4 档字号，通常是层次没想清楚。
- 字重只用 `type.weight.regular` 和 `type.weight.strong`。苹方没有 700，微软雅黑没有 500，500 在 Windows 上和 400 看起来一样。
- 字号和行高都取偶数像素，上下留白才是整数像素。不用比 `caption` 更小的字。
- 窗口窄于 `constraint.window.width-medium-min` 时，标题降一档，`title-l` 用 `title-m` 的尺寸，`title-m` 用 `title-s` 的尺寸。
- 触屏上 `ui` 换成 `type.size.ui-touch` 和 `type.line.ui-touch`。iOS Safari 遇到小于这个字号的输入框，获得焦点时会放大页面。

## 中文的规矩

- **字体顺序**：中文内容把中文字体排在前面。W3C 的中文排版需求写明破折号和省略号占两个汉字空间。实测 SF 排在前面时，16px 的破折号是 1.73 字宽，省略号是 1.57 字宽；苹方排在前面时都是 2 字宽。还有两处字体本身的偏差，不用补丁：苹方的省略号位置偏低，W3C 写的是垂直居中；Google Fonts 版思源宋体的破折号是 1.69 字宽。
- **数字**：比对用 `type.family.latin` 和 `font-variant-numeric: tabular-nums`，右对齐。实测苹方的数字不等宽，1111 只有 0000 的三分之二，`tabular-nums` 对它没有作用。
- **标点**：中文里用全角标点。破折号不能拆到两行（W3C）。连续标点的挤压靠字体：实测苹方和思源黑体会把「》（」挤成 1.5 字宽，思源宋体部分挤压，文楷不挤。
- **中英混排**：文案里中文和英文、数字之间留一个空格。用户的内容不要改，Web 上用 `text-autospace: normal` 补。W3C 写的是这个间距不多于四分之一字宽；实测苹方的空格是三分之一字宽，略宽，文楷更宽。
- **行长**：连续阅读每行不超过 `type.measure.read` 个汉字，英文不超过 80 个字符（WCAG 1.4.8，AAA）。纯英文段落的行宽用 `type.measure.read-en`；汉字的行宽放英文会超过 80 个字符，实测每行 85 个。宋体和楷体字号更大，用 `type.measure.read-large`。
- **行高**：连续阅读不低于 1.5 倍（WCAG 1.4.8，AAA）。这里取 1.75 倍，因为汉字撑满方框，没有英文那样的上下留白。
- **段落**：工具和网页用段间距，不缩进。像书一样时首行缩进两字、段间不留白（W3C）。同一篇不要混用。
- **对齐**：默认左对齐。两端对齐只在像书一样时用，这不符合 WCAG 1.4.8（AAA），是有意的取舍。
- **断行**：标题用 `text-wrap: balance`，正文用 `text-wrap: pretty`，别让最后一行只剩一个字。长网址和文件名要能断开。
- **强调**：用 `type.weight.strong`。中文没有真斜体，不用斜体，也不让浏览器合成，`font-synthesis: none`。长文可以用着重号，横排放在字下方（W3C）。
- **字距**：中文不加字距。

## 平台

| 平台 | 字体 | 字号 |
|---|---|---|
| Web | 上面的 token | 上面的 token，用 rem，跟着读的人的设置走 |
| macOS、iOS | 系统字体，不写字体名 | 用系统的文字样式，iOS 跟随动态字体 |
| Windows | 系统字体，Segoe UI 配微软雅黑 | 用系统的文字样式 |
| Android | 系统字体 | 用系统的文字样式，单位 sp |
| 终端 | 选不了，是用户的 | 选不了，层次靠粗体、暗淡、缩进、空行和位置 |

原生平台按读法选系统样式：`read` 对应正文，`title-*` 对应标题，`caption` 对应说明，不写死数字。要换字体时，同样按上面的表判断。

只在 macOS 的 Chromium 上渲染和测量过。Windows、安卓和 Safari 上的字体、数字和标点都没有看过，要在目标环境再查一遍。

## 做完检查

- 每段字说得出属于哪种读法，用的是对应的样式。
- 把字体换掉，或者关掉网页字体，层次还分得清。
- 看灰阶截图，层次还分得清。
- 阅读正文每行不超过 `type.measure.read` 个汉字，宽屏上也一样。
- 破折号和省略号是两个字宽，破折号是一条连续的线。
- 表格里的数字上下对齐，1111 和 0000 一样宽。
- 标题和段落的最后一行不只剩一个字。
- 中文没有斜体，也没有合成的粗体。
- 放大到 200%，以及把行高、段距、字距调大（WCAG 1.4.12），内容不丢。
- 用了网页字体时：确认真的加载了，记下下载量，看没加载时回退成什么样。
- 终端：`constraint.terminal.columns-default` 列和更窄时按显示宽度对齐，设置 `NO_COLOR` 和管道输出后没有控制字符。

## 还没定，问用户

1. 第 4 条让中文段落里的英文用中文字体的字形，能接受吗？比如默认样例里 Retry-After 的连字符偏长。不接受就改成西文字体在前，再单独处理破折号和省略号。建议接受，规则简单，不用额外补丁。
2. 工具界面的 `type.size.ui` 合适吗？[间距和形状](space.md)的样例可以切换疏密，在那里比。建议不变，疏密只改间距和控件高度，不改字号。
