# 交互规范

- 状态：draft
- 来源：Kotolog 实际的做法，用户定了交互沿用它。标「提案」的地方 Kotolog 没有写，是 agent 补的，用户还没看过。依据见 [notes.md](notes.md)，做界面时不用读

做界面时默认照这一页做。要偏离就在回复里说明原因。能操作的样子见[样例页](../examples/sample/README.md)。

## 反馈

反馈方式由用户接下来要做什么决定。

| 情况 | 怎么做 |
|---|---|
| 操作马上有结果 | 界面直接变，不另外提示。比如勾掉一项，圆圈和删除线马上出现 |
| 不关键的确认 | 短暂提示，停留 `interaction.feedback.toast` 后自己消失 |
| 能撤销的操作 | 带「撤销」的提示，停留 `interaction.feedback.undo` |
| 要用户恢复或处理的问题 | 留在出问题的地方，直到解决。不能只放在会自动消失的提示里 |
| 后台任务的结果 | 可以一直留着，但不抢输入焦点 |
| 新东西落位 | 落进那一行并闪一下；落点看不到时，它所在的入口亮一下、数字跳一下 |

声音和动画不能是理解状态的唯一方式。

## 撤销还是确认

默认用撤销：能撤销的操作直接做，然后给带撤销的提示。

只有撤销不了的才先确认。确认框要写清：

- 对象的名字和具体后果，影响多少东西也要写出数量。
- 这个操作不能撤销。
- 按钮写动作本身，比如「永久删除」，不写「确定」。

## 编辑和保存

- **就地编辑。** 详情就是编辑器，不做单独的编辑模式。
- **自动保存。** 停止输入 `interaction.save.idle` 后保存，不放保存按钮。
- **保存状态看得见。** 未保存、保存中、已保存、没保存上·重试、别处也改了·查看。
- **保存失败不丢东西。** 文字留在原处，给重试。没写到服务器的改动先记在本机，下次打开时恢复。
- **冲突少打扰。** 只有两边改了同一处才请用户选，其余自动合并。
- **离开前处理好。** 关闭、切换和换形态之前，先处理没保存的内容。没写完的输入按页面保留，切走再回来还在。

## 键盘

所有操作都能用键盘完成。下面的 ⌘ 在 Windows 和 Linux 上换成 Ctrl。

| 按键 | 做什么 |
|---|---|
| ⌘K | 打开搜索 |
| ↑ ↓ | 在列表里换一项 |
| Enter、空格 | 打开或展开当前项 |
| Esc | 一次退一步：先关菜单，再关弹层，再返回 |
| ⌘Enter | 长成整页 |
| ⇧Enter | 在新窗口打开 |
| Delete | 归档选中的项，可撤销 |
| ⌘ 单击、⇧ 单击、⇧↑↓ | 多选，列表底部出批量操作 |

- 单个字母的快捷键只在焦点不在输入框时生效。输入框里常用的组合键留给编辑，比如 ⌘B 加粗。
- 悬停按钮时显示名字和快捷键。图标按钮一定要有名字。
- 右键菜单和「更多」按钮内容相同。

## 拖动和手势

- 拖动和手势不能是唯一的办法，同样的事要有按钮或键盘方式。
- 移动超过 `interaction.drag.threshold` 才算拖动。触屏上按住 `interaction.drag.long-press` 再拖，避免和滚动冲突。
- 松手前先显示落点。拖动中按 Esc，东西飞回出发的位置。
- 手机上，页面任意处往右滑是返回。页面自己能左右滑的区域除外。

## 导航和返回

- **记住来处。** 返回、收回和撤销都回到来处，形态、滚动位置、筛选和输入都还在。
- **叠一层，不跳走。** 详情盖在当前页面上，原页面退后但不卸载。网址可以直达，后退回到原来的样子。
- **不开第二份。** 东西已经在别处打开时，把它带到眼前，并闪一下。

## 弹层怎么选

| 用什么 | 什么时候 |
|---|---|
| 菜单 | 一组重复的小操作 |
| 气泡 | 轻量的、跟当前位置有关的内容，比如改日期。手机上换成底部面板，控件不变 |
| 对话框 | 用户必须先回答的决定。能用撤销解决就不用它 |
| 整页或窗 | 内容多、要停留一阵。见[条、卡、页、窗](../patterns/object-forms.md) |

打开时焦点移入，关闭时回到触发的元素。Esc 只关最上面一层。气泡和菜单点外面也能关。

## 表单和输入

- **能少填就少填。** 按当前位置给默认值，比如当前所在的空间。
- **保存前先显示识别结果。** 输入「明天」这类词时，用小标签显示认出了什么，并从标题里去掉这个词。
- **提交时才校验（提案）。** 输入过程中不报错。错误写在字段旁边，说清怎么改，输入内容保留。改对后错误马上消失。
- **提交后东西落到位。** 输入框清空、焦点留在原处，方便接着写，并给带撤销的提示。

## 搜索

- ⌘K 和页面上的搜索框打开同一个搜索。没有输入时显示最近的东西。
- 输入停顿 `interaction.search.debounce` 后才查询。
- 方向键选结果，Enter 打开，Esc 关闭。关闭后焦点回到打开前的位置。
- 已经打开的东西在结果上带标记，选中时带到眼前，不开第二份。
- 没有结果时写明搜了什么，并给清除的办法（提案）。

## 动效

- 动效说明东西去了哪，不做装饰。一次只有一个东西在动，周围的内容让位。
- 变换不超过 `object.motion.page`。高频操作只用局部过渡。
- 系统开启减少动态时直接切换，焦点照常移动。

具体做法见[条、卡、页、窗](../patterns/object-forms.md)。

## 七种状态

每个交互界面都要回答这七种。

| 状态 | 默认怎么做 |
|---|---|
| 焦点 | 顺序跟阅读和操作顺序一致，焦点指示看得见。换形态后落到新的头部；弹层关闭后回到触发的元素；整页打开时，原页面设为 `inert`。 |
| 选中 | 选中是持续的状态，悬停和焦点是临时的，三者要能分开。除了颜色还要有一种线索，比如粗线或标记（提案）。多选时列表底部出批量操作。 |
| 禁用 | 提案：这个情境永远用不到就隐藏；暂时用不了就禁用，并写明原因和怎么解除。不能只靠变灰。 |
| 加载 | 提案：`interaction.loading.delay` 内有结果就不显示指示。先显示手上已有的内容，比如列表里的摘要；完整内容在稳定的外框里淡入，外框不第二次变大小。方向键快速换项时，停稳 `interaction.select.settle` 才加载详情。 |
| 空状态 | 说明这里会出现什么，并给下一步。首次使用给创建的入口；筛选没有结果时写明条件并给清除（提案）；没有权限时写明原因和找谁（提案）。 |
| 错误 | 写清错在哪、怎么恢复，保留用户的输入。留在原处直到解决。读取失败给重试。 |
| 成功 | 界面的变化本身就是反馈。不关键的用短暂提示，能撤销的带撤销。 |
