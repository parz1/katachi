# 颜色

- 状态：draft
- 来源：agent 起草的提案。用户定的有四点：不把某一类颜色一概禁止，比方案不能只换色，颜色用 12 级色阶，数值用 Radix Colors 的原值（2026-11-07）。写明 WCAG 的有出处，写明实测的是这里算出来的，其余都是提案，用户还没确认

用户在排版那一页定了「字默认不出声」，这一页把同样的判断用在颜色上。先说为什么这样用色，再说默认怎么做、什么时候换。字体和字号见[排版](typography.md)；间距还没定，样例里的都是临时值。

## 四个主张

**1. 颜色要说得出在说什么。** 屏幕上每一种色相，都要能回答「它在告诉我什么」。说不出来就不用。颜色能说的事不多，下面有张表。

**2. 颜色默认不出声。** 层次先用灰排好，色相留给真正有事的时候。这样颜色一出现，读的人马上知道发生了什么。

**3. 去掉颜色也要能用。** 颜色是第二层，第一层是文字、形状和位置。灰阶、色盲、强制颜色模式、终端关掉颜色时，意思不能丢。

**4. 明暗是读的人选的，两边都要排好。** 默认跟随系统，不替读的人选。每一级在浅色和深色下各有一个值，都要过对比度。

这四条的代价：默认没有颜色上的面貌，第一眼比较素；能点的东西要靠形状和下划线认出来。产品要被一眼认出来时，面貌要从别处来，或者用下面的强调色。

## 颜色在说什么

| 颜色在说什么 | 例子 | 默认怎么做 | 要不要色相 |
|---|---|---|---|
| 层次：先读哪个 | 正文、次要文字、分割线、背景 | 用灰那条色阶 | 不要，灰就够 |
| 状态：发生了什么 | 错误、警告、成功 | 用红、琥珀、绿三条色阶，同时有文字或图标 | 要 |
| 操作：这里能点 | 链接、主按钮、复选框 | 默认用灰的第 12 级，靠下划线和填充认出来 | 产品决定，见下面 |
| 位置：现在在这 | 选中、当前页、焦点 | 灰底加标记，焦点用 `color.focus` | 跟着强调色 |
| 分类：这些是一类 | 标签、图表 | 先靠文字和位置分 | 要一眼分开时才要，还没有定怎么用 |
| 身份：这是谁 | 品牌区、封面、插画、用户的内容 | 产品决定，可以只为了好看 | 产品决定 |

## 12 级色阶

每条色阶 12 级，每一级的数值和用途都来自 [Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)，数值没有改动。Radix 对文字的保证是按 APCA 算的（第 11、12 级在第 2 级上达到 Lc 60 和 Lc 90），这里的底线用 WCAG，所以有几级不按它原本的用途用，下表写明了。

| 级 | Radix 的用途 | 这里的角色 | 为什么不一样 |
|---|---|---|---|
| 1 | 页面背景 | `color.surface` | |
| 2 | 区块背景 | `color.surface-subtle` | |
| 3 | 控件底色 | `color.fill`、提示的底色 | |
| 4 | 控件悬停 | `color.fill-hover`、`color.selected` | |
| 5 | 控件按下或选中 | `color.fill-active` | 灰的第 11 级在这一级上只有 4.48，所以选中的底色用第 4 级 |
| 6 | 细边框和分割线 | `color.line` | |
| 7 | 控件边框和焦点环 | 不用 | 实测灰的第 7 级在第 1 级上只有 1.53，到不了 3:1 |
| 8 | 控件边框的悬停 | 不用 | 实测 1.87 |
| 9 | 实心底色 | `color.ink-disabled` | 实测蓝色第 9 级配白字只有 3.26 |
| 10 | 实心底色的悬停 | `color.control` | 灰的第 10 级有 3.70，够当控件边框 |
| 11 | 次要文字 | `color.ink-muted`、`color.accent`、实心底色 | 实心底色从第 9 级挪到这里，配文字才到 4.5 |
| 12 | 正文 | `color.ink`、实心底色的悬停 | |

下面的样例把每条色阶都列出来，标明每一级在页面背景上的对比度，够不够当文字或边框。

[12 级色阶：每一级能做什么](color/scale.html)

tokens 里有 5 条：`color.gray`（默认的灰，完全中性）、`color.red`（错误）、`color.amber`（警告）、`color.green`（成功）、`color.sand`（纸和墨）。强调色的 25 条在 [accents.css](color/accents.css)，用到才引入。

数值来自 `@radix-ui/colors` 3.0.0，MIT 授权，复制时要保留版权声明，全文见 [LICENSE-radix-colors.txt](color/LICENSE-radix-colors.txt)。Radix 还有半透明和 P3 版本，这里没有用。

## 默认和什么时候换

| 这个产品要什么 | 怎么做 | 什么时候用 | 什么时候不用 | 代价 |
|---|---|---|---|---|
| 颜色只在有事时出现（默认） | 灰加状态色，主按钮和链接用灰的第 12 级 | 工具、后台、设置，以及没有理由换的地方 | 产品要被一眼认出来时 | 第一眼比较素；能点的要靠形状和下划线 |
| 能点的才有颜色 | 选一条色阶当强调色 | 入口多、操作多；产品要有自己的身份 | 正文里链接很多，满页都是强调色时；状态很多，强调色会和状态色抢时 | 要避开状态色那几条；彩色的按钮和链接比灰更抢眼 |
| 纸和墨 | 灰换成 `color.sand` | 文字本身就是产品：长文、读书，配[排版](typography.md)里「像书一样」的排法 | 工具界面；要判断图片或内容本身颜色的地方，色调会干扰判断 | sand 的暖色调很淡，和默认的差别主要来自排法 |

- 一个界面只有一个强调色。
- 产品有自己的品牌色时用产品的，但要过一遍「做完检查」。

下面 3 个样例内容和组件完全相同，不同的只有角色指向哪条色阶。纸和墨那一版另外配了「像书一样」的排法，因为它就是给这种情况用的。每个样例都可以切换明暗；强调色那一版可以换色阶，蓝色只是开始时的举例，不是推荐。

### 选一条色阶就够

产品要用强调色时，引入 [accents.css](color/accents.css)，在根元素上写 `data-accent="blue"`。可选的 25 条：tomato、red、ruby、crimson、pink、plum、purple、violet、iris、indigo、blue、cyan、teal、jade、green、grass、brown、orange、sky、mint、lime、yellow、amber、gold、bronze。只要一条时，可以只复制那一段进产品。

校验脚本把这 25 条都算过，下面每个角色的配对都过线。其中 teal、jade、green、orange、yellow、amber 的第 11 级在浅色的第 2 级上不到 4.5（实测 4.28–4.48），这 6 条在浅色下文字和实心底色改用第 12 级，颜色会深很多，看起来接近棕或墨绿。

红色一族（tomato、red、ruby、crimson）、橙和黄（orange、amber、yellow）、绿色一族（grass、green、jade）和状态色相近，要用时状态靠文字和图标分开。

## 角色

样式里只写角色，不写第几级。角色指向某一级，这样换强调色时样式不用改。tokens 生成的 CSS 里已经有色阶和角色，[color.css](color/color.css) 补上跟随系统、纸和墨和基础元素，可以整个复制进产品。

| 角色 | 用在 | 指向 |
|---|---|---|
| `color.surface` | 页面背景 | 灰 1 |
| `color.surface-subtle` | 区块背景：代码块、表头 | 灰 2 |
| `color.surface-raised` | 弹层和浮起的面 | 浅色灰 1，深色灰 2 |
| `color.fill` | 控件底色；透明控件的悬停 | 灰 3 |
| `color.fill-hover` | 控件悬停 | 灰 4 |
| `color.fill-active` | 控件按下，上面不放次要文字 | 灰 5 |
| `color.line` | 分割线 | 灰 6 |
| `color.control` | 控件边框 | 灰 10 |
| `color.control-hover` | 控件边框的悬停 | 灰 11 |
| `color.ink` | 正文和标题 | 灰 12 |
| `color.ink-muted` | 次要文字 | 灰 11 |
| `color.ink-disabled` | 禁用的文字 | 灰 9 |
| `color.accent` | 文字里的链接 | 灰 12；选了强调色后第 11 级 |
| `color.accent-solid` | 主按钮的底色 | 灰 12；选了强调色后第 11 级 |
| `color.accent-solid-hover` | 主按钮的悬停 | 灰 11；选了强调色后第 12 级 |
| `color.accent-fill` | 带强调的浅底 | 灰 3；选了强调色后第 3 级 |
| `color.selected` | 选中项的底色 | 灰 4；选了强调色后第 4 级 |
| `color.focus` | 焦点环 | 灰 12；选了强调色后第 11 级 |
| `color.on-solid` | 实心底色上的文字 | 灰 1 |
| `color.error` | 错误的文字和图标 | 红 11 |
| `color.error-subtle` | 错误提示的底色 | 红 3 |
| `color.error-line` | 错误的边框 | 红 11 |
| `color.error-solid` | 删除按钮这类实心底色 | 红 11 |
| `color.error-solid-hover` | 实心底色的悬停 | 红 12 |
| `color.warning` | 警告的文字和图标 | 琥珀 12，第 11 级在第 3 级上不到 4.5 |
| `color.success` | 成功的文字和图标 | 绿 12，第 11 级在第 3 级上不到 4.5 |

提示的底色、边框和实心底色，成功这一组（`color.success-subtle` 等）指向的级和错误一样。警告的底色和边框也一样；`color.warning-solid` 指向琥珀 12，悬停指向灰 12，因为琥珀第 11 级配 `color.on-solid` 只有 4.49。

## 用色的规矩

- **对比度**：每个配对都声明在 tokens 里，校验脚本按 `constraint.contrast.text` 和 `constraint.contrast.non-text` 算，不够就不通过。禁用的文字 WCAG 1.4.3 不要求对比度，但要读得出。
- **灰**：默认的灰完全中性。给灰加冷暖本身就是在说话，要有理由。
- **半透明**：文字和边框不用半透明。背景一换对比度就变了，也算不出来。要叠在图片或彩色背景上时再加 Radix 的半透明版本。
- **红色**：中文语境里红色不只表示错误，还表示喜庆和上涨。中国大陆的行情习惯红涨绿跌，和错误、成功的意思正好相反。所以涨跌不要用 `color.error` 和 `color.success`。默认不上色，靠正负号；要上色时跟随产品所在市场的习惯，并提供设置。
- **状态**：状态色一定配文字或图标（WCAG 1.4.1）。红绿色盲看不出错误和成功的差别，要靠文字和图标分开。
- **链接**：文字里的链接要有下划线（WCAG 1.4.1）。导航和菜单里的靠位置认出来，可以不要。
- **选中和当前页**：底色加标记，比如竖线、下划线或勾，灰阶里也看得出。
- **强制颜色模式**：系统会替换背景和文字的颜色，所以选中不能只靠底色。不要用透明边框占位，这个模式下它会显示出来。
- **高对比度**：读的人要更高的对比度时（`prefers-contrast: more`），次要文字用 `color.ink`，分割线用 `color.control`。
- **图片和用户的内容**：不叠色调，周围用中性灰，免得干扰颜色判断。
- **格式**：tokens 用 sRGB，生成的 CSS 写 hex，和 Radix 发布的一字不差。深色的值写在 `local.katachi` 的 `dark` 里，生成 CSS 时变成 `light-dark()`。

## 平台

和「字默认不出声」一样，原生平台跟着系统走，不自己定义灰。

| 平台 | 灰和状态色 | 强调色 |
|---|---|---|
| Web | 上面的 token | 默认用灰的第 12 级，产品可以选一条色阶 |
| macOS、iOS | 系统语义色，比如 label、secondaryLabel、systemBackground、separator、systemRed，自动跟随明暗和高对比度 | 系统的 tint，产品可以设 |
| Windows | WinUI 的主题资源，比如 TextFillColorPrimaryBrush | 系统强调色 |
| Android | Material 的颜色角色，比如 colorSurface、colorOnSurface、colorError | 产品设 colorPrimary |
| 终端 | 配色是用户的。只用 16 色的名字，不指定具体颜色，不设背景 | 不用，选中靠粗体和 `>` |

终端的样子可以运行这个看，它和排版用同一个样例：

```bash
node standards/typography/terminal.mjs
```

只在 macOS 的 Chromium 上渲染和测量过。原生平台的系统色名字查过官方文档，但没有在原生环境运行过；Windows、安卓和 Safari 都没有看过，要在目标环境再查一遍。

## 做完检查

- 每种色相说得出在说什么。
- 样式里写的是角色，不是第几级，也不是具体颜色。
- 看灰阶截图，层次、选中和状态都还分得清。
- 模拟红绿色盲（浏览器开发者工具可以模拟），错误和成功靠文字或图标分得开。
- 浅色和深色都看过，不是只看一边。
- 悬停、按下、焦点、选中、禁用都有样子，用的是对应的角色。
- 强制颜色模式下，选中和焦点还在。
- 文字和控件边框的对比度不低于下限。tokens 和 25 条强调色由 `node tools/check.mjs` 算，页面上自己写的颜色要单独算。
- 文字和边框没有半透明。
- 涨跌没有用错误和成功的颜色。
- 终端：浅色和深色主题都看；设置 `NO_COLOR` 和管道输出后没有控制字符，意思不丢。

## 还没定，问用户

1. 控件边框用灰的第 10 级，对吗？这样过我们的底线，但比 Radix 原本的第 7 级深得多。想要它原本柔和的边框，就要放宽底线。建议保持，这条底线来自 WCAG。
2. 默认连强调色都不要，按钮和链接都用灰的第 12 级，对吗？建议先这样，和「字默认不出声」一致。
3. 「纸和墨」还值得留吗？换成 sand 之后暖色调很淡，和默认的差别主要来自排法。建议留，只在文字本身就是产品时用。
