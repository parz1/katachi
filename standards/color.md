# 颜色

- 状态：draft
- 来源：agent 起草的提案，用户还没确认。用户定的有三点：不把某一类颜色一概禁止，比方案不能只换色，颜色用 12 级色阶（2026-11-07）。12 级的用途来自 [Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)。写明 WCAG 的有出处，写明实测的是这里算出来的，其余都是提案

用户在排版那一页定了「字默认不出声」，这一页把同样的判断用在颜色上。先说为什么这样用色，再说默认怎么做、什么时候换。字体和字号见[排版](typography.md)；间距还没定，样例里的都是临时值。

## 四个主张

**1. 颜色要说得出在说什么。** 屏幕上每一种色相，都要能回答「它在告诉我什么」。说不出来就不用。颜色能说的事不多，下面有张表。

**2. 颜色默认不出声。** 层次先用灰排好，色相留给真正有事的时候。这样颜色一出现，读的人马上知道发生了什么。

**3. 去掉颜色也要能用。** 颜色是第二层，第一层是文字、形状和位置。灰阶、色盲、强制颜色模式、终端关掉颜色时，意思不能丢。

**4. 明暗是读的人选的，两边都要排好。** 默认跟随系统，不替读的人选。深色不是把浅色反过来，每一级在两边都单独定，单独过对比度。

这四条的代价：默认没有颜色上的面貌，第一眼比较素；能点的东西要靠形状和下划线认出来。产品要被一眼认出来时，面貌要从别处来，或者用下面的强调色。

## 颜色在说什么

| 颜色在说什么 | 例子 | 默认怎么做 | 要不要色相 |
|---|---|---|---|
| 层次：先读哪个 | 正文、次要文字、分割线、背景 | 用灰那条色阶 | 不要，灰就够 |
| 状态：发生了什么 | 错误、警告、成功 | 用红、琥珀、绿三条色阶，同时有文字或图标 | 要 |
| 操作：这里能点 | 链接、主按钮、复选框 | 默认用灰的第 12 级，靠下划线和填充认出来 | 产品决定，见下面 |
| 位置：现在在这 | 选中、当前页、焦点 | 灰底加标记，焦点用 `focus` | 跟着强调色 |
| 分类：这些是一类 | 标签、图表 | 先靠文字和位置分 | 要一眼分开时才要，还没有色板 |
| 身份：这是谁 | 品牌区、封面、插画、用户的内容 | 产品决定，可以只为了好看 | 产品决定 |

## 12 级色阶

每条色阶 12 级，每一级的用途固定。用途来自 Radix Colors，下限是这里加的，校验脚本每条色阶都算。

| 级 | 用途 | 下限 |
|---|---|---|
| 1 | 页面背景 | |
| 2 | 区块背景：代码块、表头、侧栏 | |
| 3 | 控件底色；透明控件的悬停 | |
| 4 | 控件悬停 | |
| 5 | 控件按下或选中 | |
| 6 | 分割线，只是装饰 | |
| 7 | 控件边框 | 在第 1–3 级上不低于 `constraint.contrast.non-text` |
| 8 | 控件边框的悬停 | 同上 |
| 9 | 实心底色：主按钮 | 配 `on-solid` 不低于 `constraint.contrast.text` |
| 10 | 实心底色的悬停 | 同上 |
| 11 | 次要文字 | 在第 1–5 级上不低于 `constraint.contrast.text` |
| 12 | 正文 | 同上 |

现在有 6 条色阶：`color.gray`（默认的灰，彩度是 0）、`color.red`（错误）、`color.amber`（警告）、`color.green`（成功）、`color.paper`（纸和墨）、`color.hue`（强调色）。每一级都有浅色和深色两个值。

## 数值从哪来，还要比一比

12 级是范式，每一级的具体数值有两种来源。上面的样例可以切换，下面 3 个样例也可以。

| | 自己生成 | Radix 原值 |
|---|---|---|
| 怎么来 | 按明度和彩度曲线算，现在 tokens 里的就是这个 | [@radix-ui/colors](https://github.com/radix-ui/colors) 3.0.0，[radix.css](color/radix.css) |
| 押注 | 12 级的用途和我们的下限完全对得上；任何色相都能用 | 现成的 31 条色阶，已经被很多产品用过 |
| 牺牲 | 没有被别的产品用过，生成的效果要自己调 | 在我们的下限下，要改映射才能过线，见下面 |
| 对比度 | 校验脚本全部算过，色阶页 30 格全部过线 | 按这里的下限，色阶页 30 格里浅色 23 格、深色 15 格不过线。比如浅色下，灰的第 7 级在第 1 级上 1.53，蓝色第 9 级配白字 3.26，蓝色第 11 级在第 3 级上 4.25 |
| 授权 | 自己的 | MIT，要保留版权声明 |

Radix 对文字的保证是按 APCA 算的（第 11、12 级在第 2 级上达到 Lc 60 和 Lc 90），这里的底线用 WCAG，所以它按自己的用法达不到。想用它的值，要改这些映射：控件边框从第 7 级改到第 10 级，实心底色从第 9 级改到第 11 级，琥珀和绿的提示文字从第 11 级改到第 12 级。这些改动写在 [radix.css](color/radix.css) 里，第 7、9 级就不再是它原本的用途了。改完之后，只有琥珀当强调色时还差一点：浅色下主按钮和链接是 4.49。

自己生成这版也有代价：第 6 级到第 7 级有一个明显的跳变，因为第 7 级要到 3:1 才能当控件边框。Radix 的第 7、8 级更浅，边框看起来更柔和，但这正是它不过线的地方。

## 默认和什么时候换

| 这个产品要什么 | 怎么做 | 什么时候用 | 什么时候不用 | 代价 |
|---|---|---|---|---|
| 颜色只在有事时出现（默认） | 灰加状态色，主按钮和链接用灰的第 12 级 | 工具、后台、设置，以及没有理由换的地方 | 产品要被一眼认出来时 | 第一眼比较素；能点的要靠形状和下划线 |
| 能点的才有颜色 | 选一个色相当强调色 | 入口多、操作多；产品要有自己的身份 | 正文里链接很多，满页都是强调色时；状态很多，强调色会和状态色抢时 | 色相要避开状态色；彩色的按钮和链接比灰更抢眼 |
| 纸和墨 | 灰换成 `color.paper` | 文字本身就是产品：长文、读书，配[排版](typography.md)里「像书一样」的排法 | 工具界面；要判断图片或内容本身颜色的地方，色调会干扰判断 | 整页都在说话；这种暖色纸面现在很常见，所以没有放进默认 |

- 一个界面只有一个强调色。
- 产品有自己的品牌色时用产品的，但要过一遍「做完检查」。

下面 3 个样例内容和组件完全相同，不同的只有颜色的取值。纸和墨那一版另外配了「像书一样」的排法，因为它就是给这种情况用的。每个样例都可以切换明暗；强调色那一版可以换色相，蓝色只是开始时的举例，不是推荐。

### 选一个色相就够

产品要用强调色时，在根元素上加 `data-accent`，再设 `--accent-hue`，只写一个色相。12 级的明度和彩度都在 `color.hue` 里，不用再调。

校验脚本把 360 个色相都算过，每一级的下限和下面每个角色的配对全部过线，所以选哪个都行。浅色第 9–12 级里，色相 45–133（橙黄到黄绿）和 147–252（绿到青蓝）超出普通屏幕的范围，会被裁掉一部分彩度，看起来淡一些，对比度仍然够。色相离状态色太近时（错误 27°、警告 75°、成功 150°），状态要靠文字和图标分开。

## 角色

样式里只写角色，不写第几级。角色指向某一级，这样换色阶、换强调色时样式不用改。tokens 生成的 CSS 里已经有全部色阶和角色，[color.css](color/color.css) 补上跟随系统、纸和墨和基础元素，可以整个复制进产品。

| 角色 | 用在 | 指向 |
|---|---|---|
| `color.surface` | 页面背景 | 灰 1 |
| `color.surface-subtle` | 区块背景：代码块、表头 | 灰 2 |
| `color.surface-raised` | 弹层和浮起的面 | 浅色灰 1，深色灰 2 |
| `color.fill` | 控件底色；透明控件的悬停 | 灰 3 |
| `color.fill-hover` | 控件悬停 | 灰 4 |
| `color.fill-active` | 控件按下 | 灰 5 |
| `color.line` | 分割线 | 灰 6 |
| `color.control` | 控件边框 | 灰 7 |
| `color.control-hover` | 控件边框的悬停 | 灰 8 |
| `color.ink` | 正文和标题 | 灰 12 |
| `color.ink-muted` | 次要文字 | 灰 11 |
| `color.ink-disabled` | 禁用的文字 | 灰 7 |
| `color.accent` | 文字里的链接 | 灰 12；选了色相后第 11 级 |
| `color.accent-solid` | 主按钮的底色 | 灰 12；选了色相后第 9 级 |
| `color.accent-solid-hover` | 主按钮的悬停 | 灰 11；选了色相后第 10 级 |
| `color.accent-fill` | 带强调的浅底 | 灰 3；选了色相后第 3 级 |
| `color.selected` | 选中项的底色 | 灰 5；选了色相后第 4 级 |
| `color.focus` | 焦点环 | 灰 12；选了色相后第 9 级 |
| `color.on-solid` | 实心底色上的文字 | 灰 1 |
| `color.error` | 错误的文字和图标 | 红 11 |
| `color.error-subtle` | 错误提示的底色 | 红 3 |
| `color.error-line` | 错误的边框 | 红 7 |
| `color.error-solid` | 删除按钮这类实心底色 | 红 9 |
| `color.error-solid-hover` | 实心底色的悬停 | 红 10 |

警告和成功也一样，`color.warning` 这一组指向琥珀，`color.success` 这一组指向绿。

## 用色的规矩

- **对比度**：每个配对都声明在 tokens 里，校验脚本按 `constraint.contrast.text` 和 `constraint.contrast.non-text` 算，不够就不通过。禁用的文字 WCAG 1.4.3 不要求对比度，但要读得出。
- **灰**：默认的灰完全中性，彩度是 0。给灰加冷暖本身就是在说话，要有理由。
- **深色**：背景不用纯黑，文字不用纯白。
- **半透明**：文字和边框不用半透明。背景一换对比度就变了，也算不出来。Radix 有半透明版本，这里没有做，要叠在图片或彩色背景上时再加。
- **红色**：中文语境里红色不只表示错误，还表示喜庆和上涨。中国大陆的行情习惯红涨绿跌，和错误、成功的意思正好相反。所以涨跌不要用 `color.error` 和 `color.success`。默认不上色，靠正负号；要上色时跟随产品所在市场的习惯，并提供设置。
- **状态**：状态色一定配文字或图标（WCAG 1.4.1）。红绿色盲看不出错误和成功的差别，要靠文字和图标分开。
- **链接**：文字里的链接要有下划线（WCAG 1.4.1）。导航和菜单里的靠位置认出来，可以不要。
- **选中和当前页**：底色加标记，比如竖线、下划线或勾，灰阶里也看得出。
- **强制颜色模式**：系统会替换背景和文字的颜色，所以选中不能只靠底色。不要用透明边框占位，这个模式下它会显示出来。
- **高对比度**：读的人要更高的对比度时（`prefers-contrast: more`），次要文字用 `color.ink`，分割线用 `color.control`。
- **图片和用户的内容**：不叠色调，周围用中性灰，免得干扰颜色判断。
- **格式**：tokens 用 OKLCH，明度和彩度分开，方便算对比度；同时带 hex，给读不了 OKLCH 的地方，校验脚本会确认两者一致。深色的值写在 `local.katachi` 的 `dark` 里，生成 CSS 时变成 `light-dark()`。

## 平台

和「字默认不出声」一样，原生平台跟着系统走，不自己定义灰。

| 平台 | 灰和状态色 | 强调色 |
|---|---|---|
| Web | 上面的 token | 默认用灰的第 12 级，产品可以选色相 |
| macOS、iOS | 系统语义色，比如 label、secondaryLabel、systemBackground、separator、systemRed，自动跟随明暗和高对比度 | 系统的 tint，产品可以设 |
| Windows | WinUI 的主题资源，比如 TextFillColorPrimaryBrush | 系统强调色 |
| Android | Material 的颜色角色，比如 colorSurface、colorOnSurface、colorError | 产品设 colorPrimary |
| 终端 | 配色是用户的。只用 16 色的名字，不指定具体颜色，不设背景 | 不用，选中靠粗体和 `>` |

终端的样子可以运行这个看，它和排版用同一个样例：

```bash
node standards/typography/terminal.mjs
```

只在 macOS 的 Chromium 上渲染和测量过。原生平台的系统色名字查过官方文档，但没有在原生环境运行过；Windows、安卓和 Safari 都没有看过，要在目标环境再查一遍。

## 做完检查

- 每种色相说得出在说什么。
- 样式里写的是角色，不是第几级，也不是具体颜色。
- 看灰阶截图，层次、选中和状态都还分得清。
- 模拟红绿色盲（浏览器开发者工具可以模拟），错误和成功靠文字或图标分得开。
- 浅色和深色都看过，不是只看一边。
- 悬停、按下、焦点、选中、禁用都有样子，用的是对应的那一级。
- 强制颜色模式下，选中和焦点还在。
- 文字和控件边框的对比度不低于下限。tokens 由 `node tools/check.mjs` 算，页面上自己写的颜色要单独算。
- 文字和边框没有半透明。
- 涨跌没有用错误和成功的颜色。
- 终端：浅色和深色主题都看；设置 `NO_COLOR` 和管道输出后没有控制字符，意思不丢。

## 还没定，问用户

1. 数值用自己生成的，还是 Radix 原值？建议自己生成：用途和下限对得上，任何色相都能用，也能继续让校验脚本把关。
2. 默认连强调色都不要，按钮和链接都用灰的第 12 级，对吗？建议先这样，和「字默认不出声」一致。
3. 默认的灰完全中性，「纸和墨」只在文字本身就是产品时用，对吗？建议这样，冷暖留给产品。
