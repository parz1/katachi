# 颜色

- 状态：draft
- 来源：agent 起草的提案，用户还没确认。用户定的只有两点：不把某一类颜色一概禁止，比方案不能只换色。写明 WCAG 的有出处，写明实测的是这里算出来的，其余都是提案

用户在排版那一页定了「字默认不出声」，这一页把同样的判断用在颜色上。先说为什么这样用色，再说默认怎么做、什么时候换。字体和字号见[排版](typography.md)；间距还没定，样例里的都是临时值。

## 四个主张

**1. 颜色要说得出在说什么。** 屏幕上每一种色相，都要能回答「它在告诉我什么」。说不出来就不用。颜色能说的事不多，下面有张表。

**2. 颜色默认不出声。** 层次先用灰排好，色相留给真正有事的时候。这样颜色一出现，读的人马上知道发生了什么。

**3. 去掉颜色也要能用。** 颜色是第二层，第一层是文字、形状和位置。灰阶、色盲、强制颜色模式、终端关掉颜色时，意思不能丢。

**4. 明暗是读的人选的，两边都要排好。** 默认跟随系统，不替读的人选。深色不是把浅色反过来，每个角色在两边都单独定，单独过对比度。

这四条的代价：默认没有颜色上的面貌，第一眼比较素；能点的东西要靠形状和下划线认出来。产品要被一眼认出来时，面貌要从别处来，或者用下面的强调色。

## 颜色在说什么

| 颜色在说什么 | 例子 | 默认怎么做 | 要不要色相 |
|---|---|---|---|
| 层次：先读哪个 | 正文、次要文字、分割线、背景 | 用 `ink`、`ink-muted`、`line`、`surface` | 不要，灰就够 |
| 状态：发生了什么 | 错误、警告、成功 | 用 `error`、`warning`、`success`，同时有文字或图标 | 要 |
| 操作：这里能点 | 链接、主按钮、复选框 | 用 `accent`，默认等于 `ink`，靠下划线和填充认出来 | 产品决定，见下面 |
| 位置：现在在这 | 选中、当前页、焦点 | `surface-subtle` 加标记，焦点用 `focus` | 跟着 `accent` |
| 分类：这些是一类 | 标签、图表 | 先靠文字和位置分 | 要一眼分开时才要，还没有色板 |
| 身份：这是谁 | 品牌区、封面、插画、用户的内容 | 产品决定，可以只为了好看 | 产品决定 |

## 默认和什么时候换

| 这个产品要什么 | 怎么做 | 什么时候用 | 什么时候不用 | 代价 |
|---|---|---|---|---|
| 颜色只在有事时出现（默认） | 灰加状态色，`accent` 等于 `ink` | 工具、后台、设置，以及没有理由换的地方 | 产品要被一眼认出来时 | 第一眼比较素；能点的要靠形状和下划线 |
| 能点的才有颜色 | 选一个色相当 `accent` | 入口多、操作多；产品要有自己的身份 | 正文里链接很多，满页都是强调色时；状态很多，强调色会和状态色抢时 | 色相要避开状态色；彩色的按钮和链接比灰更抢眼 |
| 纸和墨 | 表面和文字带一点暖色调，`color.paper.light.surface` 这一组 | 文字本身就是产品：长文、读书，配[排版](typography.md)里「像书一样」的排法 | 工具界面；要判断图片或内容本身颜色的地方，色调会干扰判断 | 整页都在说话；这种暖色纸面现在很常见，所以没有放进默认 |

- 一个界面只有一个强调色。
- 产品有自己的品牌色时用产品的，但要过一遍「做完检查」。

下面 3 个样例内容和组件完全相同，不同的只有颜色角色的取值。纸和墨那一版另外配了「像书一样」的排法，因为它就是给这种情况用的。每个样例都可以切换明暗；强调色那一版可以换色相，蓝色只是开始时的举例，不是推荐。

### 选一个色相就够

产品要用强调色时只选一个色相，写在 `--accent-hue`，明度和彩度用 `color.recipe.light-l`、`color.recipe.light-c`、`color.recipe.dark-l`、`color.recipe.dark-c`。

校验脚本把 360 个色相都算过，强调色放在背景上、背景色放在强调色上，全部过 `constraint.contrast.text`，所以选哪个都行，不用再调。浅色下色相 52–127（橙黄到黄绿）和 153–246（绿到青蓝）超出普通屏幕的范围，会被裁掉一部分彩度，看起来淡一些，对比度仍然够；深色下没有这个问题。色相离状态色太近时（错误 27°、警告 75–85°、成功 150°），状态要靠文字和图标分开。

## 角色

Web 用下面的 token，[color.css](color/color.css) 是现成的实现，可以整个复制进产品，它用 `light-dark()` 跟随系统。样式里只写角色，不写具体颜色。

| 角色 | 用在 | 浅色 | 深色 |
|---|---|---|---|
| `surface` | 页面背景 | `color.light.surface` | `color.dark.surface` |
| `surface-subtle` | 选中和当前项的底色、代码块 | `color.light.surface-subtle` | `color.dark.surface-subtle` |
| `surface-raised` | 弹层和浮起的面 | `color.light.surface-raised` | `color.dark.surface-raised` |
| `ink` | 正文和标题 | `color.light.ink` | `color.dark.ink` |
| `ink-muted` | 次要文字：时间、来源、提示 | `color.light.ink-muted` | `color.dark.ink-muted` |
| `ink-disabled` | 禁用的文字 | `color.light.ink-disabled` | `color.dark.ink-disabled` |
| `line` | 分割线 | `color.light.line` | `color.dark.line` |
| `control` | 控件的边界 | `color.light.control` | `color.dark.control` |
| `accent` | 链接、主按钮、复选框 | `color.light.accent` | `color.dark.accent` |
| `on-accent` | 主按钮上的文字 | `color.light.on-accent` | `color.dark.on-accent` |
| `focus` | 焦点环 | `color.light.focus` | `color.dark.focus` |
| `error` | 错误和危险 | `color.light.error` | `color.dark.error` |
| `warning` | 警告 | `color.light.warning` | `color.dark.warning` |
| `success` | 成功 | `color.light.success` | `color.dark.success` |

`error`、`warning`、`success` 各有一个 `-subtle` 版本，用作提示的底色。

## 用色的规矩

- **对比度**：每个配对都声明在 tokens 里，校验脚本按 `constraint.contrast.text` 和 `constraint.contrast.non-text` 算，不够就不通过。禁用的文字 WCAG 1.4.3 不要求对比度，但要读得出。
- **灰**：默认的灰完全中性，彩度是 0。给灰加冷暖本身就是在说话，要有理由。
- **深色**：背景不用纯黑，文字不用纯白。
- **半透明**：文字和边框不用半透明。背景一换对比度就变了，也算不出来。
- **红色**：中文语境里红色不只表示错误，还表示喜庆和上涨。中国大陆的行情习惯红涨绿跌，和错误、成功的意思正好相反。所以涨跌不要用 `error` 和 `success`。默认不上色，靠正负号；要上色时跟随产品所在市场的习惯，并提供设置。
- **状态**：状态色一定配文字或图标（WCAG 1.4.1）。红绿色盲看不出错误和成功的差别，要靠文字和图标分开。
- **链接**：文字里的链接要有下划线（WCAG 1.4.1）。导航和菜单里的靠位置认出来，可以不要。
- **选中和当前页**：底色加标记，比如竖线、下划线或勾，灰阶里也看得出。
- **强制颜色模式**：系统会替换背景和文字的颜色，所以选中不能只靠底色。不要用透明边框占位，这个模式下它会显示出来。
- **高对比度**：读的人要更高的对比度时（`prefers-contrast: more`），次要文字用 `ink`，分割线用 `control`。
- **图片和用户的内容**：不叠色调，周围用中性灰，免得干扰颜色判断。
- **格式**：tokens 用 OKLCH，明度和彩度分开，方便算对比度；同时带 hex，给读不了 OKLCH 的地方，校验脚本会确认两者一致。

## 平台

和「字默认不出声」一样，原生平台跟着系统走，不自己定义灰。

| 平台 | 灰和状态色 | 强调色 |
|---|---|---|
| Web | 上面的 token | 默认等于 `ink`，产品可以选色相 |
| macOS、iOS | 系统语义色，比如 label、secondaryLabel、systemBackground、separator、systemRed，自动跟随明暗和高对比度 | 系统的 tint，产品可以设 |
| Windows | WinUI 的主题资源，比如 TextFillColorPrimaryBrush | 系统强调色 |
| Android | Material 的颜色角色，比如 colorSurface、colorOnSurface、colorError | 产品设 colorPrimary |
| 终端 | 配色是用户的。只用 16 色的名字，不指定具体颜色，不设背景 | 不用，选中靠粗体和 `>` |

终端的样子可以运行这个看，它和排版用同一个样例：

```bash
node standards/typography/terminal.mjs
```

只在 macOS 的 Chromium 上渲染和测量过。原生平台的系统色名字查过官方文档，但没有在原生环境运行过；Windows、安卓和 Safari 都没有看过，要在目标环境再查一遍。

## 做完检查

- 每种色相说得出在说什么。
- 看灰阶截图，层次、选中和状态都还分得清。
- 模拟红绿色盲（浏览器开发者工具可以模拟），错误和成功靠文字或图标分得开。
- 浅色和深色都看过，不是只看一边。
- 强制颜色模式下，选中和焦点还在。
- 文字和控件边界的对比度不低于下限。tokens 由 `node tools/check.mjs` 算，页面上自己写的颜色要单独算。
- 文字和边框没有半透明。
- 涨跌没有用错误和成功的颜色。
- 终端：浅色和深色主题都看；设置 `NO_COLOR` 和管道输出后没有控制字符，意思不丢。

## 还没定，问用户

1. 默认连强调色都不要，按钮和链接都是墨色，对吗？也可能你想让能点的东西默认就有颜色。建议先这样，和「字默认不出声」一致。
2. 默认的灰完全中性，不带冷暖，对吗？建议中性，冷暖留给产品。
3. 「纸和墨」值得留吗？建议留，但只在文字本身就是产品时用，不进默认。
