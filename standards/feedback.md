# 反馈

- 状态：draft
- 来源：从「现在」页的试做原型来（本机的 katachi-trial-now 仓库，now-prototype 分支，提交 12d4c66）：先改后存，保存中写在那一项上，失败改回去并给「再试一次」，做完的事能撤销，读屏用隐藏的播报区。用户定的有一点：操作结果的提示浮在窗口底部（2026-11-08，比过就地、浮在底部、底部一条三版能操作的样例后选的）。写明 WCAG、Apple、Microsoft、Android 和 GOV.UK 的有出处，其余都是提案，用户还没确认

「交互」这一层的第二页：一个操作做完以后，怎么让人知道结果，怎么反悔。提示长什么样见[控件](controls.md)，这一页管说什么、放在哪、留多久、焦点去哪。

## 四个主张

**1. 每个操作都有回音。** 点了没反应，人会再点一次。成功、出错和还在做，都要看得见，读屏也读得出。

**2. 先改，再存。** 勾掉、删除这类能撤销的小操作，先把结果显示出来，再在后台保存；没存上就改回去，并且说清楚。人不用等网络。

**3. 能撤销就不确认。** 删掉之后给「撤销」，不弹窗问「确定吗」。只有撤销不了、又不常做的操作才确认。Apple 的[提醒弹窗指南](https://developer.apple.com/design/human-interface-guidelines/alerts)也这样写：常见又能撤销的操作，就算是删除，也不弹窗。

**4. 出错不丢东西。** 打的字留着，改回去的看得出来，给「再试一次」。说清出了什么事、怎么办（WCAG 3.3.1、3.3.3）。

这四条的代价：先改后存要多写「改回去」；撤销要把删掉的东西留一阵子，真删要晚一点。

## 什么时候说什么

| 结果 | 说什么 | 例子 |
|---|---|---|
| 成功 | 做了什么、对象叫什么；能撤销的跟一个「撤销」 | 删除了「设置」　撤销 |
| 还在做 | 那一项上写「保存中」，按钮换成「……中」，见[控件](controls.md)的「加载」 | 保存中 |
| 出错 | 出了什么事、现在是什么样、怎么办；能重试的跟一个「再试一次」 | 没保存上，「设置」还没完成。　再试一次 |
| 不用说 | 结果本身就看得见、又不会失败的：展开、切换页签、筛选 | |

- 成功说结果，不说「操作成功」。对象的名字写全，长了就换行。
- 出错不怪人，不只给错误代码；要给代码时放在话的后面。
- 读屏读的和看到的是同一句话；出错时加上「可以再试一次」。

## 放在哪

操作的结果，提示浮在窗口底部，这是用户定的。下面三种放法用的是同一个待办页、同一组操作，不同的只有结果的提示放在哪；保存中都写在那一项或那个按钮上。把顶上的网络换成「慢」或「保存失败」，可以看保存中和出错。

| 放法 | 怎么做 | 什么时候用 | 代价 |
|---|---|---|---|
| 浮在底部（默认） | 浮在窗口底部居中，成功的几秒后消失，出错的留到关掉或解决；Android 的 [Snackbar](https://github.com/material-components/material-components-android/blob/master/docs/components/Snackbar.md) 也是这样 | 操作的结果，没有别的理由时都用它 | 会盖住底下的内容；自己消失的「撤销」等于设了时限（WCAG 2.2.1）；键盘要走到页面最后才够得着。下面「浮在底部怎么做」的几条就是为了补这些 |
| 就地 | 提示出现在出事的地方旁边 | 表单里某一项填错：说明写在那一项下面，见[控件](controls.md)的「错误」；保存中写在那一项上 | 页面跟着提示伸缩 |
| 底部一条 | 窗口底部固定一条，占住地方，不盖住内容 | 整个应用的状态，不属于某一个操作：断网、正在同步、订阅过期 | 一直占着一条；后面的会盖住前面没解决的错 |

整个应用的状态适合 Windows [InfoBar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/infobar) 那样放在版面里、留到解决的一条，不用浮在底部的提示：它会自己消失，人回来时就看不到了。

[浮在底部（默认）：提示浮起来，过一会儿消失](feedback/toast.html)

[就地：提示放在出事的地方旁边](feedback/inline.html)

[底部一条：固定一条，只放最近的](feedback/bar.html)

## 浮在底部怎么做

[toast.js](feedback/toast.js) 和 [feedback.css](feedback/feedback.css) 是 Web 的参考实现，可以整个复制进产品，先引入[控件](controls.md)的 controls.css。

- **位置**：窗口底部居中，离边缘 `space.page`，最宽 32rem。最多叠 3 条，新的在最下面；同一件事只留最新的一条。
- **样子**：里面是控件页的提示：图标、一句话、小按钮。阴影还没定，浮起来的这一层靠 `color.line` 的边框和 `color.surface-raised` 的底分开；出错的底用 `color.error-subtle`。
- **成功**：几秒后自己消失；鼠标停在上面、焦点在里面时先不消失。几秒还没定，样例里临时用 5 秒。
- **出错**：不自己消失，带「关闭」，留到关掉或解决。
- **不抢焦点**：提示出来时焦点不动。读屏靠播报区，见下面。
- **不盖住焦点**：提示在的时候，页面底下留出它占的高度，`scroll-padding-block-end` 也留；焦点所在的控件被盖住时滚到它上面（WCAG 2.4.11）。
- **Esc**：关掉最新的一条，焦点不动。焦点在提示里时，回到出事的地方。
- **撤销不限时**：⌘Z（Windows 上 Ctrl+Z）撤销最近一次操作，提示消失了也能撤；焦点在输入框里时不管，交给输入框撤销打的字。这样「撤销」够不着、来不及时还有别的路。
- **动效**：还没定，出现和消失都不带动画。

样例里，用键盘从勾选框走到提示里的「撤销」要按 13 下 Tab，所以 ⌘Z 和 Esc 不能少。

## 留多久

- **成功**：浮在底部的过几秒消失（见上面）。就地的留到下一次操作；底部一条留到下一条来。
- **出错**：留到解决，或者人自己关掉。不自己消失。
- **撤销**：提示消失后，⌘Z 还能撤最近一次。能做到的话不限时，比如今天做完的事今天都能撤，原型里就是这样。

## 焦点

- 结果出来时焦点不动，提示不抢焦点（WCAG 4.1.3）。
- 删掉一项：焦点落在下一项，没有下一项时落在清单的标题。就地放的话，落在那一行的「撤销」上。
- 撤销以后，焦点回到恢复的那一项。提示被关掉、按钮跟着消失时，焦点回到出事的地方。
- 重画列表时，焦点放回原来那一项的同一个控件，不能丢到页面外。
- 固定在底部和浮在底部的东西，都不能盖住获得焦点的控件（WCAG 2.4.11）。

## 读屏

- 页面一开始就放好两个隐藏的播报区：`role="status"` 给成功和保存中，`role="alert"` 给出错。结果出来时往里写一句话，读屏会读出来，焦点不用动（WCAG 4.1.3）。
- 看得见的提示不用再标 `role`，免得读两遍。

## 状态

| 状态 | 怎么做 |
|---|---|
| 焦点 | 结果出来时不动；删除、撤销、关掉提示之后按上面「焦点」一节放 |
| 选中 | 反馈不改选中。撤销恢复的那一项回到原来的位置，选中和勾选也恢复 |
| 禁用 | 保存中的控件不真禁用，写 `aria-disabled="true"`，由脚本拦住重复操作 |
| 加载 | 保存中写在那一项或那个按钮上，见[控件](controls.md)；先改后存的操作，结果先显示出来 |
| 空状态 | 删到清单空了，「撤销」和 ⌘Z 还在；同时说清现在是空的、接下来能做什么 |
| 错误 | 改回去，留着打的字；浮在底部的提示说清出了什么事和怎么办，给「再试一次」，留到解决 |
| 成功 | 浮在底部说做了什么、对象叫什么，能撤销的给「撤销」，几秒后消失 |

## 平台

原生平台跟着系统的习惯。上面的主张都还适用，放法听系统的。

| 平台 | 放法 |
|---|---|
| Web | 这一页 |
| macOS、iOS | 系统控件里没有浮在底部的提示，结果就地显示；撤销接上系统的撤销（`UndoManager`） |
| Windows | 整个应用的状态用 InfoBar；一个操作的结果就地显示 |
| Android | Snackbar：浮在底部，过一会儿消失，可以带一个「撤销」或「重试」，和这里的默认一样 |
| 终端 | 结果一行一行打出来；出错写到标准错误，退出码不是 0；跑得久的给进度 |

只在 macOS 的 Chromium 上运行过样例。原生平台的做法查过官方文档，没有在原生环境运行过。

## 做完检查

- 每个操作都有看得见的结果，读屏也读得出。
- 把网络调慢、调成失败，保存中、成功、出错都走过一遍。
- 失败时改回去了，打的字没丢，有「再试一次」，重试能成功。
- 删掉的能撤销，撤销后回到原来的位置；提示消失后 ⌘Z 还能撤。
- 做完、撤销、提示消失之后，焦点都还在页面里，看得见在哪。
- 浮在底部的提示没有盖住获得焦点的控件，Esc 能关掉。
- 窄到 `constraint.reflow.width` 时，提示不横向溢出。
- 提示里的文字对比度不低于 `constraint.contrast.text`。

## 还没定，问用户

1. 删除用撤销，不弹窗确认，对吗？建议这样，只有撤销不了、又不常做的才确认。确认要用弹层，弹层还没定。
2. 浮在底部的成功提示留几秒？建议先用 5 秒：鼠标停着、焦点在里面时不消失，⌘Z 也能撤，短一点不怕来不及。
