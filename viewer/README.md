# 查看器

直接看设计库的本地页面。内容全部从仓库文件生成，刷新就是最新的。只需要 Node，没有其他依赖。

```bash
node viewer/serve.mjs
```

然后打开 `http://localhost:4173`。端口被占用时，用 `PORT` 环境变量换一个。

> **这个页面的外观只是中性外壳，不是 katachi 的视觉规范。** 不要从它的字体、颜色、圆角或布局推断审美。

## 能看什么

| 章节 | 内容 | 来源 |
|---|---|---|
| 总览 | 各类内容的数量、成熟度、路线 | `README.md` 等 |
| 探索与示例 | 方案比较和认可的界面 | `explorations/`、`examples/` |
| 审美账本 | 明确偏好、推测、待验证 | `foundations/taste.md` |
| 平台 | 每个平台的能力、要求、必查项，以及基线表格 | `platforms/` |
| Tokens | 对比度、目标尺寸、窗口尺寸类和终端尺寸的实际样子，以及全部数值 | `tokens/katachi.tokens.json` |
| 模式与状态 | 模式的应用面和状态清单 | `patterns/` |
| 内容压力 | 中英文、混排、长文本在不同宽度和截断下的样子 | `foundations/content-stress.json` |
| 参考与素材 | 已登记的参考和正式素材 | `references/`、`assets/` |
| 决策 | 决策记录 | `decisions/` |

## 比较方案

把方案放在 `explorations/YYYY-MM-<主题>/` 的顶层，页面会自动显示：

- `.html`：按选定的窗口宽度渲染，再缩放到可用空间。
- 图片：直接显示。
- `.txt`：显示纯文本，比如终端输出。

可以切换窗口宽度，也可以打开灰阶，看方案去掉颜色后是否还能区分。宽度来自 `platforms/web.md` 的必查尺寸和 tokens。认可后的界面放在 `examples/<界面>/`，用同样的方式显示。

## 规则

- 不在这里写规范内容。要改内容，就改仓库里的文件。
- 只绑定本机地址，只读，不提供以点开头的文件。
- 改了查看器的 `.mjs` 文件要重启服务；`app.css` 和 `app.js` 刷新就生效。
- 修改后运行 `node scripts/check.mjs` 和 `node scripts/check.test.mjs`。

## 限制

- 终端尺寸那部分只是示意，不是终端验证。真实效果要在真实终端里看。
- `.txt` 方案只显示纯文本，不显示颜色。
- HTML 方案写进 iframe 的 `srcdoc`，不能把查看器整页跳走，也不能打开弹窗。要完整试用就点「单独打开」。
- 只能在本机看。
