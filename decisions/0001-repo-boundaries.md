# 0001 仓库边界：只存判断和基础，不存组件库和产品规范

- 状态：采用
- 日期：2026-11-05

## 背景

本库要被多个产品引用，同时服务本人、Claude 和 Codex，并长期保持轻量。

## 决定

- 本库保存：审美账本、通用基础、平台文件、tokens、跨平台模式、参考、正式素材、认可的示例和流程。
- 产品规范放在产品仓库的 `DESIGN.md`，和产品代码一起演进。本库只提供模板。
- 组件实现放在产品仓库。本库的示例可以运行，但不是给产品引用的库。
- 目录按需创建。`examples/`、`explorations/` 等到有第一份真实内容时才出现。
- 核心内容只用 Markdown、JSON 和自包含 HTML，不依赖某个模型或工具的专属能力。
- `AGENTS.md` 是唯一的 agent 入口。`CLAUDE.md` 只用 `@AGENTS.md` 导入，并写明导入失效时打开哪个文件。

## 备选和放弃原因

- **预建组件库**：还没有审美依据，各平台也不能共用一套实现。
- **把产品规范集中放到本库**：产品改动要跨仓库提交，版本容易对不上。
- **嵌入现有产品仓库**：无法被多个产品按版本引用。

## 代价

- 产品之间复用组件要靠复制，或者以后另建组件库。
- 看某个产品的规范要去该产品的仓库。

## 什么时候重新考虑

同一段组件实现被 3 个产品复制并同步修改时，再考虑独立的组件库。
