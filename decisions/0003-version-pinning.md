# 0003 产品用 Git 子模块锁定标签版本

- 状态：试行，第一个产品接入后再评估
- 日期：2026-11-05

## 背景

多个产品要引用本库的指定版本，产品里的 Claude 和 Codex 也要能按路径读到文件。这些产品可能在任何平台上。

## 决定

- 本库用语义化标签发布（`vX.Y.Z`）。
- 产品用 Git 子模块把本库放在 `design/katachi/`，并锁定标签。
- 产品的 `DESIGN.md` 写明锁定的版本和例外。
- 构建环境取不到子模块时，只把生成的 tokens 复制进产品仓库，并在 `DESIGN.md` 记录版本。

## 备选和放弃原因

- **Git subtree**：文件直接进入产品仓库，云端 agent 最省事。但 `references/` 里版权不属于我的截图也会被复制进产品仓库（产品可能是公开的），文件还容易被就地修改。
- **npm 包**：原生项目用不上，还要多一套发布流程。
- **只写「参考 ~/Projects/katachi」**：锁不住版本，换台机器就失效。

## 代价

- 克隆时要记得 `--recurse-submodules`。云端 agent 的启动脚本要初始化子模块，并且有访问本库的权限。
- 子模块默认处于游离 HEAD 状态，不适合在里面修改。这也符合「产品里只读」的规则。
- 跨机器使用需要远程仓库，现在还没有。

## 什么时候重新考虑

第一个产品接入后，如果子模块经常造成麻烦，比如云端 agent 取不到，就改用只复制所需文件的方式。
