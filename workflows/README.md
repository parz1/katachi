# 工作流程

四个阶段回答不同的问题，产出不能互相冒充。

| 阶段 | 回答什么 | 放在哪 | 不能证明什么 | 怎样算完成 |
|---|---|---|---|---|
| 草图探索 | 结构和层次对不对 | `explorations/YYYY-MM-<主题>/` | 视觉方向、交互 | 用户选定结构，并说明理由 |
| 视觉设计 | 应该长什么样 | `explorations/YYYY-MM-<主题>/` | 交互可用、响应式 | 用户选定方向，并说明理由 |
| 交互原型 | 能不能用，各种状态是否成立 | `explorations/YYYY-MM-<主题>/`，认可后进入 `examples/<页面>/` | 生产性能、原生手感 | 通过[三项检查](review.md)，并得到用户认可 |
| 生产实现 | 在真实产品里是否成立 | 产品仓库 | — | 产品自己的测试通过，并完成[三项检查](review.md)；原生界面要在原生环境检查 |

补充约定：

- 草图用灰阶和真实内容，可以粗糙，但不能用占位文字做判断。
- `examples/` 只放用户认可的页面，未认可的都留在 `explorations/`。
- 这两个目录在有第一份真实内容时才创建。每个子目录都要有 `README.md`，校验脚本会检查。
- 产品代码留在产品仓库。`examples/` 可以放可运行的示例，但不是给产品直接引用的组件库。

## 流程文件

| 文件 | 用途 | 状态 |
|---|---|---|
| [explore.md](explore.md) | 探索方案、校准审美 | 可用，第二阶段检验 |
| [review.md](review.md) | 三项检查和验证记录 | 可用，第三阶段检验 |
| [adopt.md](adopt.md) | 产品接入和版本锁定 | 只做过本地试验，未在真实产品检验 |
| `implement.md` 和提示词 | 实现流程，以及探索、实现、审阅提示词 | 第三阶段从真实页面中提炼 |
