# 「现在」页：第一轮结构比较

- 阶段：草图探索，全部灰阶，只比较结构
- 平台：响应式 Web（`web`、`adaptive`），以及终端草图（`terminal`）
- 任务：每天打开，看今天该做什么，做完勾掉
- 内容：所有方案用同一份内容，来自 Kotolog 的原型和界面文案，最长的标题来自内容压力测试集。不是真实账号的数据

草图可以点：勾掉任务，或点一行看它怎么打开。方案由 `build.mjs` 生成，不要手改生成的文件。

## 方案

### A 现状（对照组）：按紧急程度分段

结构按 Kotolog 的截图和原型画，去掉了颜色、纸张底纹和角色，也可能和最新版本有出入。

- 分组：待处理 → 现在 → 接下来 → 未安排 → 最近活动
- 导航：左边是完整侧栏，包括 Space 列表；手机上收进顶部菜单
- 打开详情：宽屏在右边一栏，窄屏从底部弹出
- 押注：先处理最急的事，一条线往下看不用选择
- 牺牲：卡片占空间，一屏能看到的条目少；同一个项目的事分散在不同分段

### B 按项目分组，日程放旁边

- 分组：先按项目（研究、日常、Kotolog、阅读），项目内部再按紧急程度；接下来和没安排的事默认收起
- 导航：左边只留一条窄栏，因为项目已经在主内容里；手机上变成底部标签栏
- 打开详情：在原地展开
- 押注：人是按项目切换工作的，集中做完一个项目的事比按紧急程度来回跳更顺
- 牺牲：跨项目的紧急程度不再一眼可见，只能靠顶部一句话提醒；手机上日程占掉首屏一部分

### C 一张表，一屏看完

- 分组：和 A 一样按紧急程度，但只是表里的分组行；每行一条，分成标题、项目、计划、状态几列
- 导航：顶部一行，没有侧栏；底部是快捷键提示和问コトちゃん
- 打开详情：宽屏在右边预览，窄屏从底部弹出
- 操作：可以用键盘，方向键移动，`x` 完成，回车打开
- 押注：一屏看完全部，少翻页、靠键盘操作；结构也和终端几乎一样
- 牺牲：行距紧，长标题被截断，触屏上不如卡片好点，也少了温度

### D 终端草图

`kotolog now` 按同样的分段输出，纯文本，不用颜色。这是草图，不是 CLI 现在的输出。这里按列示意，真实效果要在终端里看。
