# 界面模式

跨产品可复用的界面和交互做法。每个模式都要从至少一个真实页面提炼，不写假想的模式。

产品如何选用模式（布局、密度、平台行为）写在产品的 `DESIGN.md`，不写在这里。

## 覆盖情况

| 模式 | 状态 | 来源页面 |
|---|---|---|
| 导航 | 未开始 | — |
| 列表 | 未开始 | — |
| 表单 | 未开始 | — |
| 搜索 | 未开始 | — |
| 详情 | 未开始 | — |
| 弹层 | 未开始 | — |
| 空状态与错误状态 | 未开始 | — |

第三阶段只写代表性页面实际用到的模式。

## 模式文件格式

文件放在 `patterns/<名称>.md`。

```markdown
# <模式名>

- 状态：draft / adopted / validated
- 来源：examples/<页面>/
- 平台：Web、iOS 等，差异分开写

## 适用情境和不适用情境
## 结构和行为（数值写 token 名）
## 状态（下面的清单，每行都要回答）
## 内容压力（长文本、混排、0 条、1000 条时的行为）
## 示例（链接 examples/ 或截图）
## 理由
## 例外
```

## 状态清单

每个交互模式都要回答这些问题。这里只列问题，答案来自真实页面。

| 状态 | 必须回答 | 检查方法 |
|---|---|---|
| 焦点 | 键盘顺序是什么；焦点怎么显示；弹层开关后焦点去哪 | 只用键盘走一遍 |
| 选中 | 和当前位置、悬停、焦点怎么区分；不靠颜色怎么辨认 | 看灰阶截图 |
| 禁用 | 禁用还是隐藏；用户怎么知道原因、怎么解除 | 构造不满足条件的情况 |
| 加载 | 多久后才显示指示；布局是否跳动；能否取消 | 人为放慢网络 |
| 空状态 | 首次使用、筛选无结果、无权限时分别显示什么；下一步做什么 | 清空数据 |
| 错误 | 错在哪；输入是否保留；怎么恢复 | 断网、校验失败、服务端报错 |
| 成功 | 反馈出现在哪、持续多久；能否撤销 | 走完主要操作 |
