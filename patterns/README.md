# 界面模式

跨平台可复用的界面和交互做法。每个模式都要从至少一个真实界面提炼，不写假想的模式。

每个模式分两部分：通用部分写意图和状态，平台部分写它在各平台上的做法。产品如何选用模式，写在产品的 `DESIGN.md`。

## 应用面

每格写 已验证、已映射、不适用 或 未做，含义见 [foundations/README.md](../foundations/README.md)。第三阶段只写代表性界面实际用到的模式。

## 模式文件格式

文件放在 `patterns/<名称>.md`。

```markdown
# <模式名>

- 状态：draft / adopted / validated
- 来源：examples/<界面>/

## 通用部分

### 适用情境和不适用情境
### 意图和行为（数值写 token 名）
### 状态（下面的清单，每行都要回答）
### 内容压力（长文本、混排、0 条、1000 条时的行为）
### 理由
### 例外

## 平台部分

### <平台 ID>

应用面：已验证 / 已映射 / 不适用 / 未做
做法、示例和这个平台的额外状态。
```

## 状态清单

每个交互模式都要回答这些问题。这里只列问题，答案来自真实界面。平台文件还可能列出额外状态，比如 POS 的外设故障。

| 状态 | 必须回答 | 检查方法 |
|---|---|---|
| 焦点 | 操作顺序是什么；当前位置怎么显示；弹层开关后焦点去哪 | 只用这个平台的非指针输入走一遍 |
| 选中 | 和当前位置、悬停、焦点怎么区分；不靠颜色怎么辨认 | 看灰阶截图，终端看无色输出 |
| 禁用 | 禁用还是隐藏；用户怎么知道原因、怎么解除 | 构造不满足条件的情况 |
| 加载 | 多久后才显示指示；布局是否跳动；能否取消 | 人为放慢网络或操作 |
| 空状态 | 首次使用、筛选无结果、无权限时分别显示什么；下一步做什么 | 清空数据 |
| 错误 | 错在哪；输入是否保留；怎么恢复 | 断网、校验失败、服务端报错 |
| 成功 | 反馈出现在哪、持续多久；能否撤销 | 走完主要操作 |
