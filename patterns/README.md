# 界面模式

跨平台可复用的界面和交互做法。每个模式都要从至少一个真实界面提炼，不写假想的模式。

每个模式既写通用的意图和状态，也写它在各平台上的做法。产品如何选用模式，写在产品的 `DESIGN.md`。

## 模式文件格式

文件放在 `patterns/<名称>.md`，配套的截图和能运行的例子放在 `patterns/<名称>/`。查看器会把模式页整页显示出来。

样板是 [object-forms.md](object-forms.md)。它是样章，这个格式还在等用户判断厚度够不够。厚度来自真实内容：没有内容的节直接省略，不留空标题，只有「状态」不能省。

```markdown
# <模式名>

- 状态：draft / adopted / validated
- 来源：真实界面或产品文档的路径，以及提交

## 一句话
## 看一眼（真实截图；一段话只放一个 .html 链接时，查看器会就地运行它）
## 什么时候用（适合和不适合的情境）
## 骨架、规则和变换（做法和理由）
## 数值（只写 token 名）
## 动效
## 状态（下面的清单，每行都要回答，没定义也要写明）
## 内容压力（长文本、混排、0 条、1000 条时的行为）
## 平台（每个平台一节，写应用面和差异）
## 怎么实现（能复制的最小例子，以及来源产品的代码位置）
## 照着做时检查
## 不做什么（写清情境）
## 认可记录（日期和原话；不是当面听到的要注明）
## 通用还是专属（用最窄平台测试来分）
## 还没定
## 这一页的依据和检查（读过什么、渲染过什么、没检查什么）
```

## 状态清单

每个交互模式都要回答这些问题。这里只列问题，答案来自真实界面。平台文件还可能列出额外的情况，比如终端的管道输出、折叠屏的姿态变化。

| 状态 | 必须回答 | 检查方法 |
|---|---|---|
| 焦点 | 操作顺序是什么；当前位置怎么显示；弹层开关后焦点去哪 | 只用这个平台的非指针输入走一遍 |
| 选中 | 和当前位置、悬停、焦点怎么区分；不靠颜色怎么辨认 | 看灰阶截图，终端看无色输出 |
| 禁用 | 禁用还是隐藏；用户怎么知道原因、怎么解除 | 构造不满足条件的情况 |
| 加载 | 多久后才显示指示；布局是否跳动；能否取消 | 人为放慢网络或操作 |
| 空状态 | 首次使用、筛选无结果、无权限时分别显示什么；下一步做什么 | 清空数据 |
| 错误 | 错在哪；输入是否保留；怎么恢复 | 断网、校验失败、服务端报错 |
| 成功 | 反馈出现在哪、持续多久；能否撤销 | 走完主要操作 |
