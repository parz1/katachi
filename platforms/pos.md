# pos POS 机

包括收银台、手持收银设备和顾客屏。

> 没有查到通用的官方 POS 界面规范。这里的能力和场景是常见情况，接入真实设备时要按实际修订，不要当成设备事实。

## 能力

- 单位：取决于设备系统，按实机确定。
- 显示：屏幕尺寸和分辨率固定；可能有顾客屏；可能有强光和较大的观看角度。小票是单独的输出：黑白，按打印机的列宽排版。
- 输入：触摸为主，可能有硬件键盘、扫码枪和读卡器。
- 场景：高频重复操作，常常站着用，旁边可能有人排队；设备多人共用、长时间运行；可能断网。

## 平台要求

- BASE-1：除了计算数值，还要在实机和实际光线下看。
- BASE-4：每条主要流程都要确定用哪种输入完成。扫码枪和硬件键盘的输入不能丢，也不能落到错误的位置。
- BASE-5：没有通用下限。以设备系统的下限为起点，比如 Android 设备的 `constraint.target.android-min`，再按实机的物理尺寸和使用场景确定。频繁点按的目标可以更大；后果严重的目标要留更大的间距，并远离内容边缘。依据 Microsoft 的 [Targeting 指南](https://learn.microsoft.com/en-us/windows/apps/develop/input/guidelines-for-targeting)。
- BASE-6：屏幕固定，通常不需要重排，但要在实际分辨率下完整可用。系统字号可调时要支持。
- BASE-8：金额、数量和合计不能被截断。长商品名和小票都要测试。
- 可访问性：[WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/) 把 POS 列为封闭功能的例子：用户可能无法使用自己的辅助技术，只满足 WCAG 不足以保证可访问。要看设备有没有内置辅助功能，或由产品自己提供替代方式。
- 支付：支付和 PIN 输入界面可能受支付硬件和 PCI PTS 等要求限制，能否自定义要查设备和支付 SDK 的文档。这里还没有核实具体规定。

## 额外状态

除了[状态清单](../patterns/README.md)，还要回答：

- 打印机缺纸或卡纸、扫码失败、读卡失败时怎么办。
- 断网时能否继续收银，恢复后怎么同步。
- 支付结果未知时怎么处理，不能造成重复扣款。

## 必查

- 实机的分辨率和物理尺寸。
- 连续快速操作；站立时的阅读距离。
- 实际光线。
- 每种外设故障。
- 断网、支付失败和支付超时。
- 小票实际打印，包括中文和长商品名。
- 顾客屏的内容，以及不该让顾客看到的内容。

## 验证

- 先用什么查：按实机分辨率做的 Web 原型或设备模拟器，只能验证结构和内容。
- 最终验证：实机，最好在真实收银场景里。
