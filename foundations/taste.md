# 审美账本

记录用户的审美偏好和设计判断。三类内容必须分开，用法见 [AGENT_GUIDE.md](../AGENT_GUIDE.md)。

**当前状态：还没有做过任何视觉比较。** 下面的明确偏好全部来自初始需求，说的是如何做判断，不是具体的视觉选择。

条目规则：

- ID 递增且不复用：明确偏好用 `S-`，推测用 `I-`，待验证用 `O-`。
- 明确偏好必须有原话、日期和范围，不要改写成比原话更宽的规则。
- 范围按当时看到的具体画面写，不要外推。指代不清的话（比如「那个灰色」）要写明是哪个方案的哪个位置，判断不了就先问。想推广到更大范围，另写一条推测。
- 推测必须有证据、验证方式和置信度。
- 推测或待验证项只有在用户确认后才能转为明确偏好。新条目注明「来自 I-xxx」或「来自 O-xxx」，并删除原条目，历史看 Git。
- 否定的偏好要带情境：「在 X 里不用 Y，因为 Z」，不写一概禁止。

## 推测

### I-001 中文和拉丁字母、数字之间可能倾向留空格

- 证据：初始需求全文都这样写，例如「UI 设计资产」「最多问 3 个」。
- 验证方式：在代表性页面比较不留空格、手动留空格、浏览器自动间距三种。
- 置信度：低。书写习惯不一定等于界面偏好。

### I-002 产品以工具型和内容型为主，不是营销页

- 证据：初始需求列出的模式是导航、列表、表单、搜索、详情、弹层、空状态与错误状态，没有落地页。
- 验证方式：选定代表性页面时直接确认。
- 置信度：中。

### I-003 Apple 原生平台是重要目标之一

- 证据：初始需求多次提到原生应用；`~/Projects/Designs/` 里有 `Kotolog-LOGO.icon`，看起来是 Apple Icon Composer 文件。只看了文件名，没有打开内容。
- 验证方式：选定代表性页面时确认平台。
- 置信度：中。

## 待验证

### O-001 层次主要靠什么建立：留白、分隔线、底色还是阴影

- 比较方式：同一页面、同样内容，分别以其中一种为主做版本。

### O-002 舒适的信息密度是多少

- 比较方式：用真实内容做疏、中、密三档，数一屏能看到多少条，并实际试一次扫读。

### O-003 正文字号和行高

- 比较方式：中文、英文、混排各一段，同一栏宽下比较 3 组字号和行高。

### O-004 字体气质，以及中文和西文如何搭配

- 比较方式：在同一页面比较 2–3 组字体，同时看中文、英文、数字和混排。

### O-005 中性色和强调色怎么用

- 比较方式：结构定下后再比较中性色的冷暖、强调色的使用范围和面积。

### O-006 形状语言：圆角、描边、控件轮廓

- 比较方式：同一组控件比较 3 种处理，放回页面里看，不单独看控件。

### O-007 动效的存在感

- 比较方式：用可运行原型，让同一个操作分别几乎无动效、短促、带弹性。

### O-008 浅色和深色模式的优先级

- 比较方式：先确认常用环境，再在代表性页面上比较两种模式。

### O-009 Web 和原生之间应该有多像

- 比较方式：第一个原生产品接入时，同一页面分别做 Web 和原生版本后对照。
