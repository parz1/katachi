# 通用基线

所有平台共同的底线，来自可访问性标准和平台规范，不是审美选择。

- 这里写目标。各平台的具体做法和数值在 [platforms/](../platforms/README.md)，每条规则在哪些平台上怎么用，见那里的基线表格。
- 数值只在 [tokens](../tokens/katachi.tokens.json) 里维护，这里只写 token 名。
- 这些是下限，不是推荐尺寸。舒适的尺寸由产品密度决定（见 `taste.md` 的 O-002）。
- 没有列出的就没有下限。比如标准没有规定行高的最小值，它是待验证的审美判断（见 `taste.md` 的 O-003）。
- 下面每条规则的状态都是 standard；BASE-8 除外，它来自用户要求（S-006），也默认遵守。
- 示例待补：第三阶段随代表性界面补充，现在还没有视觉示例。
- 交互状态的要求见 [patterns/README.md](../patterns/README.md)。
- WCAG 为 Web 而写。用在其他平台时参考 [WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/)，它是说明性文档，不设定要求。

### BASE-1 文字对比度

- 适用：所有传达信息的文字，包括次要文字和占位提示。
- 做法：普通文字不低于 `constraint.contrast.text`，大号文字（按 WCAG 定义）不低于 `constraint.contrast.text-large`。
- 理由：对比度不足的文字，在强光、低质量屏幕或视力下降时很难读。
- 例外：纯装饰文字、logo、真正禁用的控件。
- 依据：WCAG 2.2 SC 1.4.3。

### BASE-2 非文字对比度

- 适用：识别控件所必需的边界、图标、焦点指示、图表中的关键图形。
- 做法：与相邻颜色的对比度不低于 `constraint.contrast.non-text`。
- 理由：用户要先看得出控件和状态，才能操作。
- 例外：纯装饰图形、禁用的控件。
- 依据：WCAG 2.2 SC 1.4.11。

### BASE-3 不只靠颜色传达信息

- 适用：选中、错误、必填、状态、图表系列。
- 做法：除颜色外至少再有一种线索，比如文字、图标、形状或位置。检查方法是看灰阶截图，仍能分辨才算通过。
- 理由：色觉差异和强光环境下，单靠颜色的信息会丢失。
- 例外：无。
- 依据：WCAG 2.2 SC 1.4.1。

### BASE-4 操作方式和当前位置

- 适用：所有可操作的界面。
- 做法：主要流程都能用这个平台的主要输入方式和辅助技术完成；用户始终知道当前位置，焦点或选中位置可见，不被遮挡；弹层打开时焦点移入，关闭时回到触发元素。
- 理由：键盘和辅助技术的用户依赖焦点判断自己的位置。
- 例外：无。
- 依据：WCAG 2.2 SC 2.1.1、2.4.3、2.4.7、2.4.11。

### BASE-5 目标尺寸

- 适用：所有可点击或可轻点的控件。
- 做法：不低于所在平台的下限，数值见平台文件。平台没有通用下限时，平台文件要说明怎么确定。
- 理由：目标过小容易误触，对行动不便的用户尤其困难。
- 例外：句子里的行内链接；旁边有同功能且足够大的替代目标。
- 依据：WCAG 2.2 SC 2.5.8；各平台规范。

### BASE-6 缩放和重排

- 适用：所有包含文字的界面。
- 做法：可用空间或文字设置变化时，内容和功能不丢失。具体要求见平台文件。
- 理由：很多人依赖放大或调整文字才能阅读。
- 例外：表格、地图、图表等必须二维展示的内容不受重排要求限制。
- 依据：WCAG 2.2 SC 1.4.4、1.4.10、1.4.12。

### BASE-7 尊重减少动态设置

- 适用：所有带动画的界面。
- 做法：系统开启减少动态时，去掉或替换位移、缩放、视差等非必要动画。
- 理由：大幅运动可能让部分用户不适。
- 例外：传达必要信息的进度指示可以保留。
- 依据：WCAG 2.2 SC 2.3.3（AAA 级，这里主动采纳）。

### BASE-8 内容不能破坏界面

- 适用：所有页面和模式。
- 做法：用真实内容和 [content-stress.json](content-stress.json) 检查中文、英文、混排、长文本和极端数量。内容可以截断，但要有办法看到全文；不能溢出容器，也不能挤掉主要操作。
- 理由：理想内容做出的设计，遇到真实内容常常会坏。
- 例外：无。
- 依据：`taste.md` 的 S-006。
